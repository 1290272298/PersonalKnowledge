# 01. Contact Builder 介绍

## 学习目标
了解 Contact Builder 的定位、主要功能，以及它与 Email Studio 和 Data Extension 的关系。

## 1. 产品定位
Contact Builder 是 Marketing Cloud Engagement 中管理和组织 Contact 数据的工具。它帮助用户查看 Contact、配置数据关系、管理 Contact 数据来源，并为 Journey Builder 的条件判断和跨渠道沟通提供数据基础。

## 2. 主要功能
| 功能 | 用途 |
|---|---|
| Contact Configuration | 配置 Contact 处理相关设置 |
| Data Designer | 设计 Contact 数据模型与关系 |
| Data Extensions | 管理用于存储 Contact 相关信息的 DE |
| Imports / Data Sources | 查看和管理数据来源（具体入口依 UI） |
| All Contacts | 查看 Contact 记录和关联信息 |

## 3. Contact 与 Subscriber
- Contact 是跨渠道沟通中的统一对象，可关联 Email、Mobile、Push 等渠道数据。
- Subscriber 是特定渠道的订阅者，例如 Email Studio 中的 Email Subscriber。
- 所有 Email Subscriber 都关联到 Contact，但并非所有 Contact 都是 Email Subscriber。

## 4. Contact Builder 与 Data Extension
DE 是存储数据的表结构；Contact Builder 的 Data Designer 用于定义这些数据如何与 Contact 关联。仅仅创建 DE 并不会自动建立正确的 Contact Model 关系。需要明确关联字段、主键和 Attribute Group。

## 5. 常见应用
- Journey Builder 根据客户等级、订单历史等属性分支。
- 将 Email 与 Mobile 等渠道身份关联到同一个 Contact。
- 在 Contact 视图中理解客户的相关数据与互动信息。

## 6. 操作建议
1. 先确定需要统一识别的业务实体。
2. 定义 Contact Key。
3. 设计数据表和关联字段。
4. 使用 Data Designer 配置 Attribute Group。
5. 验证关系与 Journey 中字段的可用性。
6. 上线后监控 Contact 数量和模型变化。

## 常见问题
**创建 DE 后为什么 Journey 中找不到字段？** 检查 DE 是否纳入正确 Attribute Group、关系是否有效，以及 Journey 使用的是 Journey Data 还是 Contact Data。

**Contact 与 Subscriber 是否一一对应？** 不一定。一个 Contact 可关联不同渠道的订阅身份。

## Checklist
- [ ] Contact / Subscriber 概念区分清楚
- [ ] Contact Key 规则确定
- [ ] DE 和数据模型职责分清
- [ ] 关系配置与实际业务一致
