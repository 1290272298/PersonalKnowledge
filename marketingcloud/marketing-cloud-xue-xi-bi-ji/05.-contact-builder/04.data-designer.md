# 04. Data Designer

## 学习目标
掌握 Data Designer 的基本用途、数据源关系配置和变更风险。

## 1. 功能
Data Designer 是 Contact Builder 中设计 Contact 数据关系的工具。它以 Contact 为中心展示 Attribute Groups，并帮助定义不同 DE 中的数据如何关联到同一个 Contact。

## 2. 设计前准备
- Contact Key 的标准及来源。
- DE 的字段、主键和数据类型。
- 每个 DE 的粒度：客户一行、订单一行、事件一行等。
- 关系基数：一对一还是一对多。
- Journey / Send / API 对这些字段的实际使用方式。

## 3. 配置流程
1. 打开 Contact Builder → Data Designer。
2. 选择或创建 Attribute Group。
3. 添加目标 DE。
4. 选择用于关联的字段。
5. 确认关系方向和字段类型。
6. 保存并检查模型图。
7. 使用测试 Contact 验证属性可见性和分支结果。

## 4. 数据模型示例
| DE | 粒度 | 关联字段 |
|---|---|---|
| Customer | 每个客户一行 | ContactKey |
| Order | 每笔订单一行 | ContactKey |
| Preference | 每个客户一行 | ContactKey |

Customer / Preference 可能是一对一；Customer / Order 通常是一对多。若 Journey 需要“最近一笔订单金额”，建议先在 SQL 中计算并产出每个 Contact 一行的结果，再用于判断。

## 5. 变更管理
修改关系前，评估：
- 正在运行的 Journey 是否使用该关系
- Decision Split / Exit Criteria 是否引用相关字段
- DE 是否正在被 SQL、Import 或 API 更新
- 字段删除、重命名或类型变更是否影响其他流程

先在测试环境验证，再按变更窗口实施。

## 常见问题
- 数据模型中看不到 DE：检查 DE 类型、权限和是否满足添加要求。
- 关系字段无法匹配：检查字段名、类型、主键和数据值。
- 修改后 Journey 行为改变：检查依赖该关系的 Contact Data 条件。

## Checklist
- [ ] DE 粒度和主键明确
- [ ] 关系字段类型一致
- [ ] 一对多处理规则明确
- [ ] 下游 Journey 依赖已盘点
- [ ] 变更有测试与回退方案
