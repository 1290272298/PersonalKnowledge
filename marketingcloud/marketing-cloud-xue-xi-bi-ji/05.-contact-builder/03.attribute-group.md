# 03. Attribute Group

## 学习目标
理解 Attribute Group 的作用、组成和关系设计原则。

## 1. 什么是 Attribute Group
Attribute Group 是 Contact Builder 中用于逻辑组织相关数据源并定义它们与 Contact 关系的结构。它让营销人员能够从 Contact 出发访问相关业务数据。

例如客户主档与订单表可通过 CustomerId / ContactKey 关联，供 Journey Builder 使用订单属性判断客户路径。

## 2. 常见结构
```
Contact
  ├── Customer Profile DE
  ├── Order DE
  └── Preference DE
```
每个 Attribute Group 可包含一个或多个相关数据源，并通过关系字段连接。

## 3. 设计要点
- 根节点/主数据源应能正确关联 Contact。
- 关联字段的数据类型和实际值必须一致。
- 选择真正稳定的 Contact Key，不要用显示名称或可变 Email。
- 一对多数据需要明确如何使用；例如一个客户有多笔订单，不能假设只会返回一条。
- 只添加业务需要的属性，避免过度复杂的模型。

## 4. 配置步骤
1. 在 Contact Builder 打开 Data Designer。
2. 新建或选择 Attribute Group。
3. 添加相关 Data Extension。
4. 将数据源关系连接到 Contact 或其他数据源。
5. 指定关联字段并检查关系方向/基数。
6. 保存后使用实际样本验证 Journey 中可见的数据。

## 5. 常见问题
- 字段无法在 Journey 中选择：检查 DE 是否加入 Attribute Group、关系是否有效及权限。
- 找到多条订单但无法判断目标订单：需在数据层预处理出明确的最新订单/目标订单，而不是依赖不确定的多行关系。
- 关系保存失败：检查字段类型、主键和关系字段配置。

## Checklist
- [ ] Attribute Group 的业务目的明确
- [ ] 关联字段稳定且类型一致
- [ ] 一对多数据的选择规则明确
- [ ] 不必要的数据源未加入
- [ ] Journey 分支已用真实数据验证
