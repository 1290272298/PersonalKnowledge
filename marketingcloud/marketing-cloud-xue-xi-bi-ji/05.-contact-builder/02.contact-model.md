# 02. Contact Model

## 学习目标
理解 Contact Model 的核心对象、身份标识和数据组织方式。

## 1. 什么是 Contact Model
Contact Model 是 Marketing Cloud Engagement 对 Contact 及其关联属性/数据源的组织模型。Contact 通常处于模型中心，其他数据通过关系关联到 Contact。

## 2. 核心标识
| 标识 | 说明 | 设计建议 |
|---|---|---|
| Contact Key | 由业务定义的跨渠道稳定标识 | 全渠道统一、不可随意变更 |
| Contact ID | 平台内部系统标识 | 不作为业务主键替代品 |
| Subscriber Key | Email Studio Subscriber 的标识 | 与 Contact Key 保持一致 |
| Email Address | 邮箱地址 | 可变，不建议默认作为主键 |

## 3. Contact 属性
Contact 可关联 Profile Attributes（例如姓名、地区、会员等级）和 Behavioral Attributes（例如点击、购买等行为）。属性的可用性取决于数据来源、关系配置和数据更新。

## 4. Contact 与 Subscriber
Email Subscriber 是渠道层面的订阅身份；Contact 是跨渠道的统一实体。退订、Held 等渠道状态不等同于 Contact 是否存在。删除 Contact 也不是简单删除一个 Email Subscriber，需要评估所有渠道和关联数据。

## 5. 模型设计步骤
1. 确定业务实体及其唯一识别规则。
2. 定义 Contact Key。
3. 列出 Profile、订单、互动等数据源。
4. 确定数据表主键与 Contact 关联字段。
5. 确定一对一、一对多关系。
6. 在 Data Designer 中建立关系并验证。

## 6. 常见问题
- 同一客户出现多个 Contact：通常先检查不同来源的 Contact Key 是否一致。
- 一个 Email Address 对应多个 Contact：若业务允许家庭共享邮箱或多账户，Subscriber Key 仍需区分个人/实体。
- Contact 数量异常增长：检查导入、发送、API 和 Journey 是否使用了不一致或临时 Key。

## Checklist
- [ ] Contact Key 不是易变字段
- [ ] Contact ID 与业务 Key 未混用
- [ ] Subscriber / Contact 关系理解正确
- [ ] Contact 数据源和生命周期明确
