# 05. Relationship

## 学习目标
理解 Contact 数据关系的基数、关联键和一对多关系对营销判断的影响。

## 1. 常见关系
- 一对一：一个 Contact 对应一条偏好设置记录。
- 一对多：一个 Contact 对应多笔订单或多条行为记录。
- 多对多：通常需要通过中间关系表表达，不应随意直接建模。

## 2. 关联字段
关系字段必须在数据语义上代表同一实体，且字段类型和值格式一致。最常见的是用 Contact Key 关联客户数据。不要用 Email Address 作为关联键，除非业务确实没有稳定 Key 且已评估邮箱变更风险。

## 3. 一对多风险
例如一个 Contact 有 5 笔订单。Journey 条件“订单金额大于 100”究竟表示任意一笔、最新一笔，还是累计金额？必须先定义业务语义。建议通过 SQL 预处理出每个 Contact 一行的指标，避免模糊的多行判断。

## 4. 示例
```
Customer(ContactKey) 1 ─── N Order(ContactKey, OrderId)
```
若要判断“最近订单金额”，可以在 SQL 中按 ContactKey 分组并按 OrderDate 排序，形成一行一 Contact 的 LatestOrder DE。

## 5. 排查
- 关系匹配不到：检查 Key 值、空格、大小写、类型和数据完整性。
- 返回结果不符合预期：检查基数及多行记录的业务语义。
- Journey Split 不准确：确认字段来源是 Journey Data 还是 Contact Data，并检查模型关系。

## Checklist
- [ ] 关系键代表相同业务实体
- [ ] 字段类型一致
- [ ] 关系基数正确
- [ ] 一对多场景有明确汇总/选取规则
- [ ] 关系变更已做下游影响分析
