# 08. MuleSoft Integration

## 学习目标
理解 MuleSoft 在 Marketing Cloud 集成架构中的定位，以及 API、数据映射、错误处理和安全治理。

## 1. MuleSoft 的角色
MuleSoft 可作为集成层连接 CRM、ERP、订单系统、网站和 Marketing Cloud。它负责 API 编排、数据转换、路由、认证管理和错误处理。MuleSoft 并不会自动替代 Marketing Cloud 内部的 Contact Model 或 Journey 配置。

## 2. 典型架构
```
CRM / ERP / Web
      ↓
 MuleSoft API Layer
      ↓ Transform / Validate
 OAuth / Marketing Cloud API
      ↓
 DE / Event / Send / Asset
```

## 3. 设计步骤
1. 明确系统边界、数据所有权和调用方向。
2. 定义 API Contract、字段映射和业务唯一 ID。
3. 配置 Marketing Cloud Installed Package 和 OAuth。
4. 在 MuleSoft 安全配置中保存 Client Secret。
5. 实现 Token 管理、请求转换和响应处理。
6. 设计超时、限流、重试、死信和人工补偿。
7. 建立端到端日志与监控。

## 4. 错误处理
- 认证错误：检查 Secret、Token、Scope 和 Endpoint。
- 数据校验错误：返回可定位的业务错误，不无限重试。
- 限流 / 暂时性错误：有限重试并采用退避策略。
- 超时：先确认目标操作是否已执行，再决定是否重试。
- 重复事件：通过业务 ID / 幂等键防止重复写入或发送。

## 5. 安全与治理
使用最小权限、凭证轮换、TLS、日志脱敏和环境隔离。对个人数据定义传输目的、保留期限和访问控制。不要在日志中记录完整 Payload 中的敏感字段。

## Checklist
- [ ] API Contract 与字段映射已评审
- [ ] OAuth 凭证安全保存
- [ ] Token / Timeout / Retry 策略完成
- [ ] 幂等和死信处理完成
- [ ] 端到端监控与告警就绪
- [ ] 开发/测试/生产环境隔离
