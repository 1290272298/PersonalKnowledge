# 05. Data Extension API

## 学习目标
了解通过 API 管理 Data Extension 元数据和数据行的常见方式，并掌握主键、批量写入和更新语义。

## 1. 两类操作
- Metadata：创建、查询或管理 DE 定义、字段和属性。
- Data Rows：向已存在的 DE 查询、插入、更新或删除数据行。

具体操作由 REST / SOAP API 的资源能力决定；不能将“更新 DE 结构”和“更新 DE 行数据”混为一谈。

## 2. REST 与 SOAP
REST API 可通过 Data Extension / Data Extension Rows 相关资源进行操作；SOAP API 可使用 DataExtensionObject 等对象。资源路径、过滤能力和支持的操作请以官方 Reference 为准。

## 3. 主键和 Upsert
写入前确认：
- DE Customer Key / External Key
- 字段名、类型、长度和必填约束
- 主键组合
- 新增、更新、Upsert 的语义
- 同一业务记录重复请求时如何避免重复

如果没有主键或业务唯一键，重试可能产生重复数据。

## 4. 字段缺失行为
更新时仅提交部分字段是否保留其他字段、空值是否覆盖、批量接口如何处理，取决于具体 API 操作。必须在测试 DE 中验证，不要推断所有 API 的字段缺失语义一致。

## 5. 设计流程
1. 先创建并验证 DE 结构。
2. 使用 Customer Key 确定目标 DE。
3. 按 API 文档构建请求。
4. 使用测试数据验证新增、更新、重复请求和空字段。
5. 对批量写入设计分页、分批和错误重试。
6. 对结果数量和关键字段进行对账。

## 6. 常见问题
- 找不到 DE：检查 Customer Key、MID / BU 和共享 DE 权限。
- 主键冲突：检查重复记录和复合主键。
- 部分字段被覆盖：确认接口的更新语义和请求 payload。
- 数据未写入：检查字段类型、必填项、权限和 API 响应。

## Checklist
- [ ] Metadata 与 Row 操作区分
- [ ] DE Customer Key 正确
- [ ] 主键和字段 schema 明确
- [ ] Upsert / 缺失字段语义已测试
- [ ] 分批、限流和重试完成
- [ ] 写入结果有对账
