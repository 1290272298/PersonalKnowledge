# 02. REST API

## 学习目标
理解 REST API 的请求结构、OAuth Token、常见资源和错误处理。

## 1. REST API 特点
REST API 使用 HTTP 方法和 JSON 请求/响应操作 Marketing Cloud Engagement 资源。具体资源、方法和权限以官方 API Reference 为准。

## 2. Endpoint
REST Base URI 通常采用当前 Installed Package 提供的子域名形式：
`https://{subdomain}.rest.marketingcloudapis.com`
不要直接照抄其他账号的 subdomain。

## 3. 请求基本结构
```http
POST /v2/token HTTP/1.1
Host: {subdomain}.auth.marketingcloudapis.com
Content-Type: application/json
```
Token 请求应发往 Auth Base URI；业务资源请求发往 REST Base URI，并在 Authorization Header 中携带 Bearer Token。完整请求体和资源路径以对应 API 文档为准。

## 4. 常见资源类别
- Data Extensions / Data Extension Rows
- Contacts / Subscribers
- Journeys / Events
- Messaging / Sends
- Assets / Content
- Automations / Tracking（按 API 支持范围）

## 5. HTTP 方法
| 方法 | 常见语义 |
|---|---|
| GET | 查询资源 |
| POST | 创建资源或触发操作 |
| PATCH | 更新部分字段 |
| PUT | 按资源定义替换/更新 |
| DELETE | 删除资源 |

不要仅凭 HTTP 方法判断操作一定幂等；必须阅读具体 Endpoint 说明。

## 6. 错误处理
- 400：请求字段或格式错误。
- 401：Token 无效、过期或认证信息不正确。
- 403：权限或 Scope 不足。
- 404：资源或 Endpoint 不存在。
- 429：限流；按响应提示退避。
- 5xx：服务端暂时异常，可按幂等策略有限重试。

记录 HTTP Status、Correlation / Request ID（如有）、业务 ID 和脱敏错误摘要。不要记录 Token 或 Secret。
