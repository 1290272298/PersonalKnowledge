# 04. OAuth

## 学习目标
理解 Installed Package、Client ID / Secret、Access Token、Scope 和 Token 生命周期。

## 1. OAuth 2.0 流程
```
Installed Package
  ↓ Client ID / Secret
Auth Base URI
  ↓ Token Request
Access Token + Expires In
  ↓ Bearer Token
REST / SOAP API
```

## 2. 创建 API Integration
在 Marketing Cloud Setup → Apps → Installed Packages 中创建 Package，添加 API Integration 组件。根据外部系统调用模式选择 Server-to-Server 等适当类型，并只授予业务所需 Scope。

## 3. 获取 Token
Token 请求发送到当前 Package 提供的 Auth Base URI，常见 Token Endpoint 为 `/v2/token`。请求中包含 grant_type、client_id、client_secret，以及适用时的 account_id / scope 等参数。字段组合以当前 OAuth 文档和 Integration 类型为准。

## 4. Access Token 使用
业务请求使用：
`Authorization: Bearer {access_token}`
Token 有有效期，客户端应根据 expires_in 管理缓存和刷新。不要每个 API 请求都重新获取 Token，也不要在 Token 失效后无限循环重试。

## 5. Scope 与 BU
Scope 决定 API Integration 可访问的能力；Account / MID 上下文决定请求所针对的账号范围。Token 不会自动继承所有子 BU 权限。需要访问 Child BU 时，按官方机制指定正确的账号上下文，并确认该集成具有相应权限。

## 6. 安全要求
- Secret 存放在 Secret Manager / 安全配置中。
- 不提交到 Git、前端代码、日志或工单截图。
- 定期轮换凭证并制定泄露应急流程。
- 生产与测试使用独立 Package / 凭证。
- 按最小权限原则设置 Scope。

## 常见问题
- invalid_client：检查 Client ID / Secret、Package 状态和 Auth Base URI。
- unauthorized / forbidden：检查 Token、Scope、MID 上下文和用户权限。
- Token 过期：检查 expires_in 与缓存逻辑。
- Parent BU 可用、Child BU 不可用：检查 account_id / BU 上下文和对应权限。
