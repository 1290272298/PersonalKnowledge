# 01. API 介绍

## 学习目标
理解 Marketing Cloud Engagement API 的用途、API 类型、认证方式和集成前提。

## 1. API 能力
Marketing Cloud Engagement 提供 REST API 和 SOAP API，用于与外部系统集成。REST API 覆盖多种平台资源；SOAP API 对部分 Email 相关对象和操作具有较完整支持。两者并非完全功能对等，某些业务场景需要组合使用。

## 2. REST 与 SOAP
| 项目 | REST API | SOAP API |
|---|---|---|
| 数据格式 | JSON | XML / SOAP Envelope |
| 交互风格 | Resource / HTTP Method | WSDL / SOAP Operation |
| 常见用途 | 多渠道资源、数据、发送等 | Subscriber、Tracking、Automation 等传统功能 |
| 认证 | OAuth 2.0 | 可使用 OAuth Access Token |
| 端点 | REST Base URI | SOAP Base URI / WSDL |

## 3. API Integration
在 Setup → Apps → Installed Packages 创建 Package，并添加 API Integration 组件。根据调用方式选择适当的集成类型和权限。Client ID / Client Secret 用于获取 Token，不应当作普通用户名密码使用。

## 4. Base URI
不要硬编码网上示例中的固定 MID 或实例域名。应从 Installed Package 详情获取当前账号的 Auth Base URI、REST Base URI 和 SOAP Base URI。错误的 Tenant / Subdomain Endpoint 可能导致请求失败或连接到错误环境。

## 5. 集成设计
1. 明确业务系统与 Marketing Cloud 的数据流方向。
2. 确认所需 API 能力和 REST / SOAP 选择。
3. 创建 Installed Package 和 API Integration。
4. 配置最小必要 Scope。
5. 获取 Token 并调用测试资源。
6. 设计错误处理、日志和重试。
7. 完成安全评审后部署。

## 常见问题
- 401 / Unauthorized：检查 Token、Scope、过期时间和账号。
- 403 / Forbidden：检查 API Integration 权限和目标资源权限。
- 404：检查 Subdomain、Base URI、资源路径和 MID 上下文。
- API 可调用但数据不可见：检查 BU、共享 DE 和资源权限。

## Checklist
- [ ] API 类型和资源范围明确
- [ ] Package 与 Scope 已配置
- [ ] Endpoint 从当前账号获取
- [ ] 测试环境和生产环境隔离
- [ ] 错误处理和安全策略完成
