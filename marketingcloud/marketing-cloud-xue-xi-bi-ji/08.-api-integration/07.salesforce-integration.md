# 07. Salesforce Integration

## 学习目标
理解 Marketing Cloud 与 Salesforce CRM 的常见集成模式、权限和数据同步风险。

## 1. 常见集成方式
- Marketing Cloud Connect：连接 Marketing Cloud Engagement 与 Salesforce CRM，支持特定 CRM 数据、发送和 Journey 场景。
- REST / SOAP API：由外部系统或中间件主动调用。
- 文件 / SFTP：通过批量文件交换数据。
- MuleSoft：作为集成层协调多个系统。

这些方式可以组合使用，但数据同步机制、实时性和权限模型不同。

## 2. Marketing Cloud Connect
实施前确认：
- CRM 与 Marketing Cloud 的连接状态
- 集成用户和权限集
- 目标对象、字段级安全和记录访问权限
- Contact / Lead / Subscriber Key 的映射
- BU、共享 DE 和发送上下文

## 3. 数据同步
不要假定 CRM 数据变化后立即出现在所有 Marketing Cloud 入口或 Contact Data 中。确认同步类型、频率、过滤条件、字段映射和错误队列。

## 4. 设计原则
- 以稳定业务 Key 关联 CRM 与 Marketing Cloud。
- 明确哪个系统是字段主数据来源。
- 对双向同步字段定义冲突解决规则。
- 避免循环更新和重复触发。
- 保护 CRM / Marketing Cloud 凭证并限制权限。

## 5. 常见问题
- CRM 数据未同步：检查 Connector、同步定义、对象/字段权限和同步错误。
- Journey 找不到 CRM 字段：检查 Contact Model、关系和数据同步。
- Contact 重复：检查 CRM ID、Contact Key 和 Subscriber Key 映射。
- 更新失败：检查连接用户、记录访问权限、字段级安全和必填字段。

## Checklist
- [ ] 集成方式与业务实时性匹配
- [ ] 连接用户权限已核对
- [ ] 主数据来源和字段映射明确
- [ ] Contact Key 映射一致
- [ ] 同步延迟、错误和循环更新已考虑
