# 03. SOAP API

## 学习目标
理解 SOAP API、WSDL、Service Endpoint 和 OAuth Access Token 的使用方式。

## 1. SOAP API
SOAP API 使用 XML Envelope 和 WSDL 定义的 Operation 访问 Marketing Cloud Engagement 功能。部分 Subscriber、Tracking、Automation、Triggered Send 和 Email 相关功能常见于 SOAP API。

## 2. WSDL / Endpoint
使用当前账号在 Account Settings / Cloud Preferences 或 Installed Package 中显示的 SOAP Base URI。常见格式：
- WSDL：`https://{subdomain}.soap.marketingcloudapis.com/etframework.wsdl`
- Service：`https://{subdomain}.soap.marketingcloudapis.com/Service.asmx`

具体地址以账号显示为准。不要将其他 Tenant 的 Endpoint 用于当前账号。

## 3. 认证
推荐使用 OAuth Access Token。先通过 Auth Service 获取 Token，再在 SOAP Header 中按官方要求传递访问令牌。传统 UsernameToken 方式安全性较低，不应作为新集成的默认方案。

## 4. 调用流程
1. 获取当前账号 WSDL。
2. 在客户端生成 SOAP Proxy / Client。
3. 获取 OAuth Token。
4. 设置 SOAP Header 和 Service Endpoint。
5. 调用目标 Operation。
6. 解析 SOAP Fault 和业务响应。
7. 记录脱敏日志并处理重试。

## 5. SOAP Fault 排查
检查 XML Namespace、Operation 名称、必填属性、对象权限、Token 和 Tenant Endpoint。SOAP Fault 与 HTTP Status 可能同时包含信息，应一并记录。

## Checklist
- [ ] WSDL 来自当前账号
- [ ] Service Endpoint 正确
- [ ] OAuth Token 可用
- [ ] XML Namespace / Operation 正确
- [ ] SOAP Fault 有统一处理
- [ ] 请求日志不包含 Secret / Token
