# 06. Send API

## 学习目标
理解 Marketing Cloud API 触发发送的常见方式、发送定义、受众数据和防重复设计。

## 1. 常见发送方式
Marketing Cloud Engagement 可通过支持的 REST / SOAP API 触发发送，例如 Triggered Send / Message Definition 等场景。不同 API 适用不同发送类型和消息能力，需根据官方文档选型。

## 2. 发送前提
- Email / Message 内容已创建并发布。
- 发送定义、Send Classification、Sender Profile、Delivery Profile 等配置正确。
- 发送请求字段与消息个性化字段匹配。
- Contact Key / Subscriber Key 与 DE / Contact Model 一致。
- 收件人订阅状态和发送资格符合政策。

## 3. 请求设计
请求通常包含目标发送定义、Contact / Subscriber 信息和个性化属性。具体 JSON / SOAP 结构取决于所用 Endpoint。不要把 API 请求返回成功等同于邮件已送达收件箱。

## 4. 幂等与防重复
业务系统应为每次业务触发生成唯一业务 ID，并保存发送请求状态。超时后不要盲目重新提交：先查询发送状态或业务日志，确认原请求是否已受理，避免重复发送。

## 5. 监控
区分：
- API Request Accepted：接口受理
- Send Processing：发送处理
- Sent / Delivered：发送与投递统计
- Bounce / Unsubscribe：后续反馈事件

## 常见问题
- API 返回错误：检查 Token、Scope、发送定义 Key 和请求字段。
- API 成功但未收到邮件：检查发送资格、Subscriber Status、Held、抑制规则和 Tracking。
- 重复发送：检查超时重试、业务幂等 ID 和调用端日志。
- 个性化字段为空：检查请求字段名与模板属性名。

## Checklist
- [ ] 发送定义和内容正确
- [ ] Contact Key / Subscriber Key 正确
- [ ] 发送配置与资格检查完成
- [ ] 业务 ID 和防重复机制完成
- [ ] API 受理与实际发送监控分离
