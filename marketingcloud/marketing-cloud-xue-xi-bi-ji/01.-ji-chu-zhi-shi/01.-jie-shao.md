# 01. Marketing Cloud Engagement 介绍

## 1. 本页学习目标

学习完本页，应能够说明：
- Marketing Cloud Engagement 解决什么业务问题。
- 它与 Salesforce CRM、Data 360、Marketing Cloud Personalization、Account Engagement 的边界。
- 一次营销活动从数据准备到发送、行为反馈的完整闭环。
- 为什么数据身份、订阅许可、发送配置和数据质量必须一起设计。

## 2. 产品定位

**Marketing Cloud Engagement（下文简称 Engagement）** 是 Salesforce 的数字客户沟通与营销执行平台。企业可以使用客户数据、内容、渠道和自动化能力，管理批量营销、事件触发沟通以及跨渠道客户旅程。

它不只是“邮件发送工具”。邮件只是一个渠道；实际项目还需要处理客户身份、订阅状态、目标人群、内容、发送策略、行为反馈、数据更新和权限治理。

典型闭环：

```
业务目标
  ↓
数据来源与身份匹配
  ↓
受众筛选 / 排除 / Consent 检查
  ↓
内容与发送策略
  ↓
Email / SMS / Push 等渠道
  ↓
客户行为与发送结果
  ↓
分析、优化、下一次营销动作
```

## 3. 产品边界：不要把名称相近的产品当成同一个模块

| 产品 / 能力 | 主要职责 | 与 Engagement 的关系 |
|---|---|---|
| Marketing Cloud Engagement | Email、Mobile、Journey、Automation、内容与发送执行 | 本知识库主要学习对象 |
| Sales Cloud / Service Cloud | CRM 销售、服务、客户与业务记录 | 可通过 Marketing Cloud Connect 等方式集成 |
| Data 360（原 Data Cloud 品牌） | 跨来源数据整合、统一身份、数据激活等 | 可向 Engagement 提供数据/受众能力，需看集成与许可 |
| Marketing Cloud Personalization | 实时网站/应用体验、行为驱动个性化与推荐 | 独立产品能力，不等于 Engagement 内的动态邮件内容 |
| Marketing Cloud Account Engagement | B2B 营销自动化与潜客培育 | 与 Engagement 的目标场景、数据模型和产品能力不同 |

注意：产品套餐、功能名称、集成方式会变化。不要仅凭 Salesforce 品牌相同就认为功能自动包含在当前账号中。

## 4. Marketing Automation 的本质

营销自动化不是简单地把人工步骤改成定时任务，而是把业务规则、客户状态、触发条件和后续动作明确化。

例如欢迎旅程：

1. 客户在网站提交注册。
2. 系统创建客户身份和必要的订阅记录。
3. 满足同意与发送资格后进入 Welcome Journey。
4. 发送欢迎邮件。
5. 等待一段时间，按规则检查客户行为。
6. 根据行为发送后续内容或结束旅程。
7. 将发送和互动结果用于后续分析。

自动化流程必须同时考虑：重复事件、身份冲突、退订、Bounce、数据延迟、失败重试和重复发送。

## 5. 典型能力分层

### 5.1 数据与身份
- Contact Builder：管理 Contact 数据及 Attribute Group 关系。
- Data Extension：保存结构化数据。
- Subscriber / Contact Key：识别订阅者和跨渠道 Contact。
- 导入、API、SQL 和集成：将数据送入或加工成可用结构。

### 5.2 受众与内容
- 受众可以来自 DE、筛选结果、事件或已集成的数据源。
- Content Builder 用于创建、组织和复用内容资产。
- 个性化内容需要正确的字段、关系、空值处理和回退内容。

### 5.3 执行与编排
- Email Studio：邮件创建、发送和订阅者相关管理。
- Automation Studio：按计划或触发条件执行数据处理与任务。
- Journey Builder：按 Contact 进入、等待、条件分支和活动执行客户旅程。
- Mobile 相关能力：按账号启用情况支持 SMS、Push 等渠道。

### 5.4 反馈与治理
- Tracking / Data Views：分析发送、打开、点击、Bounce 等事件（数据保留期限有限）。
- 角色、权限、BU 和共享机制：控制用户与资源访问。
- Consent、退订、抑制名单、数据保留和删除：保障合规与数据治理。

## 6. 一个端到端案例：汽车品牌新车型推广

假设有客户主数据、购车记录、网站浏览记录：

| 数据 | 示例字段 | 用途 |
|---|---|---|
| 客户主数据 | CustomerID、Email、Locale | 身份和联系地址 |
| 购车记录 | CustomerID、Model、PurchaseDate | 购买历史 |
| 浏览记录 | CustomerID、Product、EventTime | 兴趣信号 |
| Consent | CustomerID、Channel、Purpose、Status | 发送资格 |

流程：
1. 通过稳定的 CustomerID 对齐数据，不用 Email 作为跨渠道主键。
2. 将源数据导入适当的 DE，并验证记录数、主键和更新时间。
3. 使用 SQL / Segment 逻辑形成目标受众，排除退订、无效地址和不符合目的限制的对象。
4. Content Builder 准备邮件内容，设置缺失字段时的默认文案。
5. Email Studio 或 Journey Builder 按发送场景执行。
6. 读取 Tracking，分析发送成功、Bounce、点击和转化。
7. 将业务结果回写或供下一轮分群使用。

## 7. 设计时必须回答的问题

| 维度 | 必须确认 |
|---|---|
| 业务目标 | 促销、通知、欢迎、续约还是服务提醒？ |
| 身份 | Contact Key / Subscriber Key 来自哪个系统？是否稳定？ |
| 许可 | 哪个渠道、哪个目的、哪个品牌范围允许发送？ |
| 数据 | 数据来源、刷新频率、延迟、主键和保留期限是什么？ |
| 内容 | 缺失字段、语言、时区、动态内容回退如何处理？ |
| 执行 | 单次 Send、Automation 还是 Journey？为什么？ |
| 风险 | 重复进入、重复发送、错误受众、退订同步如何防止？ |
| 监控 | 如何对账目标人数、实际发送、Not Sent 和 Bounce？ |

## 8. 常见误区

- **误区：Engagement 就是 Email。** 实际还包括数据、内容、自动化、Journey 和多渠道能力。
- **误区：有客户 Email 就可以发送。** 还要确认 Subscriber、订阅状态、Consent、Send Classification、Suppression 等。
- **误区：Data 360、Personalization 和 Engagement 是同一个产品。** 它们有不同的数据模型和职责，集成能力也取决于许可与配置。
- **误区：打开率可以完全代表客户兴趣。** 隐私代理、邮件客户端预加载等因素可能影响 Open 指标，需结合点击、转化等业务指标。
- **误区：AI 生成内容就代表可以直接发送。** 仍需人工审核事实、品牌、隐私、许可和内容合规。
