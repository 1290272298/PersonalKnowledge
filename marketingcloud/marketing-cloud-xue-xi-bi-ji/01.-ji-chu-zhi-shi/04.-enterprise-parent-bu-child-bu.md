# 04. Enterprise / Parent BU / Child BU

## 1. 学习目标

能够画出 Enterprise Account 与 BU 的层级关系；区分 Enterprise、Parent BU 和 Child BU 的概念；理解层级结构如何影响资源、用户、共享和 Subscriber 管理。

## 2. 概念关系

Marketing Cloud Engagement Enterprise / Enterprise 2.0 环境通常由一个 Enterprise Account 管理多个 Business Units。

```
Enterprise Account
  └─ Parent Business Unit
       ├─ Child BU - Japan
       ├─ Child BU - China
       └─ Child BU - Brand A
```

注意：
- Enterprise Account 是企业级账号组织层级。
- Parent BU 是层级中的上级 BU，可承担企业管理和共享资源管理职责，也可以承载自身业务。
- Child BU 是下级 BU，通常用于独立品牌、地区或业务运营。
- 具体结构、管理能力和共享范围取决于账号类型与配置；不能将示意图视为所有账号的固定结构。

## 3. Parent BU 与 Child BU 的职责差异

| 维度 | Parent BU | Child BU |
|---|---|---|
| 组织角色 | 上层 BU，常承担企业级管理职责 | 下层业务执行单元 |
| 业务执行 | 可以运行自己的营销活动 | 可独立运行本地活动 |
| 用户 | 可参与企业用户和 BU 管理 | 使用被分配到该 BU 的用户 |
| 资源 | 可管理或提供共享资源（按配置） | 可使用本地及授权共享资源 |
| 数据 | 可拥有本地 DE，也可能维护共享数据 | 通常维护自身业务 DE |
| 发送 | 可在自身上下文发送 | 在自身 BU 上下文发送 |

不要把“Parent”理解为所有数据都必须集中存放的地方，也不要把“Child”理解为完全独立的产品实例。

## 4. 层级对实际操作的影响

### 4.1 用户与访问
用户是否能切换到某个 BU，取决于 BU 分配和账号设置；进入 BU 后能执行哪些操作，还取决于角色和具体权限。

### 4.2 数据与内容
本地 DE、Email、Content、Journey 和 Automation 通常需要在正确 BU 中管理。共享资源可以减少重复，但需要明确资源所有者、权限和修改影响。

### 4.3 API
API 调用必须确认 Token 对应的账号上下文以及请求使用的目标 BU。不要将 Parent MID 与 Child MID 随意替换。

### 4.4 Subscriber / Contact
资源按 BU 管理，不代表同一个人的 Contact / Subscriber 状态也必然按 BU 独立。尤其要确认 All Subscribers、Subscriber Key、Contact Key、退订类型和发送上下文。

## 5. 示例：多地区企业

```
Global Enterprise
  └─ Global Parent BU
       ├─ Japan BU
       │    ├─ JP_Customer_DE
       │    ├─ JP_Welcome_Journey
       │    └─ JP_Daily_Import
       ├─ China BU
       │    ├─ CN_Customer_DE
       │    └─ CN_Campaign_Journey
       └─ Shared Resources
            ├─ Shared Email Blocks
            └─ Shared Reference Data
```

该示例仅表示可能的设计方式。共享资源的实际目录和权限配置应以当前账号为准。

## 6. 项目设计时应建立的清单

| 项目 | 应记录内容 |
|---|---|
| Enterprise | 企业账号名称、EID / 企业层级识别信息（按内部安全规范保存） |
| BU | BU 名称、MID、Parent 关系、业务用途 |
| 用户 | 用户、BU Access、Role、特殊权限 |
| 数据 | DE 所属 BU、External Key、共享状态、数据所有者 |
| 内容 | 本地/共享资产、维护者、发布流程 |
| Automation | 执行 BU、Schedule、输入输出资源 |
| Journey | 所属 BU、Entry Source、Contact Key 规则 |
| API | Installed Package、Scope、Token 上下文、目标 MID |
| 退订 | Global / Master / List-level 等范围和同步机制 |

不要将真实 MID、Token、Secret 或客户数据直接写入公开学习笔记。

## 7. 常见问题排查

### 问题：在 Child BU 找不到 Parent BU 的 DE
检查该 DE 是否放在可共享位置、是否使用 Shared Data Extension、用户是否有访问权限，以及当前 BU 是否正确。

### 问题：API 返回资源不存在或无权限
确认 Token 的账号上下文、目标 MID、资源 External Key、Installed Package Scope 和用户权限。

### 问题：一个 BU 的退订似乎影响另一个 BU
先确认是否为同一 Enterprise、Subscriber Key 是否相同、退订范围是什么，再检查发送上下文和集成方式。不要仅凭 BU 层级推断。
