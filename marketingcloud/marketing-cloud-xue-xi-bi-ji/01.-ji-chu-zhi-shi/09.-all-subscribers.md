# 09. All Subscribers

## 1. 学习目标

理解 All Subscribers 在 Email Studio 中的用途；区分它与 DE、Publication List、Contact Builder 和 Tracking 的关系；能够按正确顺序排查 Subscriber 是否具备发送资格。

## 2. All Subscribers 是什么

All Subscribers 是 Email Studio 中管理 Email Subscriber 及其全局订阅状态的重要位置。常见字段包括 Subscriber Key、Email Address 和 Status。

它不是客户主数据仓库，也不是所有业务属性的唯一存储位置。详细客户资料、交易和业务状态通常保存在 DE 或其他数据源。

## 3. All Subscribers 与 DE

| All Subscribers | Data Extension |
|---|---|
| 管理 Email Subscriber 身份与状态 | 保存业务定义的结构化记录 |
| Subscriber Key 是关键识别值 | 可包含 Subscriber Key / Contact Key |
| Status 影响 Email 发送资格 | DE 的 Status 字段只是业务数据 |
| 不是完整客户主数据表 | 可保存大量业务属性和历史数据 |

向 Sendable DE 发送时，Subscriber Key 用于匹配 Subscriber；Email Address 的实际取值还可能受 Subscriber 是否已存在、发送类型和集成上下文影响。不能假设 DE 中 Email 字段永远覆盖 All Subscribers 中的地址。

## 4. All Subscribers 与 Publication List / List

All Subscribers 的全局状态与 List / Publication List 的订阅关系需要区分：
- Global / Master Unsubscribe：订阅者在账号范围内退订。
- List-level Unsubscribe：对特定 List 的订阅关系退订。
- Publication List：用于按邮件类别或主题管理订阅偏好（具体发送方式取决于配置）。

发送时不仅要看 All Subscribers，也要看发送对象、Publication List、Suppression 和 Send Classification。

## 5. All Subscribers 与 BU

Enterprise 环境中的 Subscriber 管理不能简单理解为每个 BU 都有完全独立的一份 All Subscribers。跨 BU 问题需要确认：
1. 是否属于同一 Enterprise。
2. Subscriber Key 是否一致。
3. 退订发生在哪个范围。
4. 发送来自哪个 BU。
5. 是否使用 Marketing Cloud Connect 或其他集成发送。
6. 是否存在额外的业务级 Consent / Suppression。

不要把 BU 中 DE 的资源隔离，直接推断为 Subscriber 状态也按 BU 完全隔离。

## 6. Email Address 更新行为

当向 Sendable DE 发送时，Subscriber 是否已存在会影响 Email Address 的使用规则。Salesforce 官方说明：普通 DE 发送中，已存在 Subscriber 时通常使用 All Subscribers 中的 Email Address；新 Subscriber 则可能使用 DE 中的地址创建 Subscriber。Journey Builder 和 Salesforce Data Extension 等场景可能有不同处理。

因此，地址变更场景必须根据发送类型和当前产品行为验证，不能只修改 DE 字段就假设 All Subscribers 已同步。

## 7. 发送资格排查

```
确认目标记录与 Subscriber Key
  ↓
查 All Subscribers 的 Email Address / Status
  ↓
确认 Global / List / Publication List 退订
  ↓
检查 Send Classification 与 Suppression
  ↓
检查 List Detective / 地址质量
  ↓
检查 Send Job / Not Sent / Bounce 证据
```

如果发送结果不明确，可以结合 Tracking、Not Sent Extract、Journey Activity 的 Contact Details 等证据排查。

## 8. 常见误区

- **All Subscribers = 所有客户资料。** 它主要管理 Email Subscriber 信息和状态。
- **DE 中 Email Address 一定是最终发送地址。** 需要看 Subscriber 是否已存在及发送上下文。
- **All Subscribers 的 Unsubscribed 只影响一封邮件。** Global / Master Unsubscribe 的影响范围更广。
- **每个 BU 都有完全独立的 All Subscribers。** Enterprise 环境不能这样简单理解。
- **DE 中 Status = Active 就能发送。** 必须检查 Subscriber Status 和其他发送资格。

## 9. 本页 Checklist

- [ ] Subscriber Key 与目标记录匹配。
- [ ] All Subscribers 的 Email Address 和 Status 已检查。
- [ ] Global / List-level / Publication List 退订范围已确认。
- [ ] Send Classification、Suppression 和 List Detective 已检查。
- [ ] 已确认实际发送地址的取值规则。
- [ ] Not Sent / Bounce / Journey History 等证据已保存。
