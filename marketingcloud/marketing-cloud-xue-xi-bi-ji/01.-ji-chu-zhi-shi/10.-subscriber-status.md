# 10. Subscriber Status

## 1. 学习目标

理解常见 Subscriber Status 的含义，区分退订与投递失败；知道状态与 Send Classification、Suppression 和发送上下文共同决定实际发送资格。

## 2. 常见状态

| Status | 含义 | 处理方向 |
|---|---|---|
| Active | Subscriber 当前处于活动状态 | 仍需检查其他发送资格 |
| Unsubscribed | Subscriber 已退订 | 按退订范围和发送分类处理，不能随意恢复 |
| Bounced | Subscriber 发生退信相关状态/记录 | 查看 Bounce 类型、原因和后续状态 |
| Held（Undeliverable） | 因持续或符合条件的投递失败而被系统置为不可投递 | 先确认地址可投递性，不能为了发送直接激活 |

不同页面、报告或 API 可能显示不同的状态字段或描述。以 All Subscribers / 当前官方定义为准。

## 3. Active 不等于一定可发送

即使 Status = Active，也可能因以下原因不发送：
- List Detective 排除。
- Suppression List 或 Exclusion Script。
- 发送对象字段或关系不正确。
- Send Classification / 发送定义不符合要求。
- Consent、业务规则或渠道资格不满足。
- 地址格式、发送配置或内容问题。

因此“Active”只代表 Subscriber 状态，不代表完整的最终 Sendability 判定。

## 4. Unsubscribed 与 Held 的区别

- Unsubscribed 表示客户选择或被记录为不再接收某类/范围的邮件，是订阅许可问题。
- Held 表示地址处于不可投递状态，通常与持续 Bounce 有关，是投递能力问题。

两者不能互相替代。重新激活 Unsubscribed 可能违反客户意愿；重新激活 Held 可能再次产生 Bounce 并损害发送信誉。

## 5. Bounce 与 Held

Bounce 是一次发送事件的退信结果；Held 是 Subscriber 后续可能出现的状态。并不是每次 Bounce 都立即等于 Held。需要检查 Bounce Category、SMTP Diagnostic、历史连续失败和 Subscriber Properties。

Salesforce 官方建议，只有确认地址重新可投递后，才评估 Held 的恢复操作。不要为了测试或提高发送数量而批量恢复。

## 6. Status 与 Send Classification

实际是否发送取决于 Subscriber Status 与 Send Classification 等规则的组合。Commercial 与 Transactional 发送的处理可能不同；Transactional 不能被用作绕过商业邮件退订的手段。事务性消息必须确实符合业务和法律定义，并按企业政策管理。

不要在知识库中写“某状态一定能/不能发送”而不说明 Send Classification 和账号上下文。

## 7. Status 与 DE 业务字段

```
All Subscribers.Status = Marketing Cloud Subscriber 状态
DE_Customer.Status     = 企业自定义业务字段
```

两个字段即使都叫 Status，也可能完全不同。例如 DE 中的 CustomerStatus = Active 不能覆盖 All Subscribers 中的 Unsubscribed。

## 8. 排查邮件未发送的顺序

1. 确认 Subscriber Key / Contact Key。
2. 确认当前 BU、发送类型和 Send Classification。
3. 查看 All Subscribers Status。
4. 检查 Global / List-level Unsubscribe。
5. 检查 Suppression、List Detective 和 Consent。
6. 查看 Not Sent / Tracking / Bounce 诊断。
7. 修复根因后先小范围验证。

## 9. 恢复状态的风险控制

- Unsubscribed：只有取得有效重新订阅/同意依据，并遵循业务、法律和企业流程后才恢复。
- Held：先确认 Email Address 正确且可投递，再按 Salesforce 文档和企业审批流程操作。
- 不要将 Held 批量改为 Active 作为常规排障手段。
- 保留恢复前后的状态、原因、批准人和验证结果。

- [ ] 区分 Unsubscribed 与 Held。
