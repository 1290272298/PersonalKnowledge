# 06. Delivery Profile

## 1. 学习目标
理解 Delivery Profile 在邮件发送中的职责，能够识别 IP Address、Header、Footer 配置，并检查它与 Send Classification 的关联。

## 2. Delivery Profile 是什么
Delivery Profile 用于集中定义邮件投递相关信息。它可以被多个发送复用，并由 Send Classification 引用。

常见配置包括：
- IP Address：发送时使用的 IP 选择方式。
- Header：邮件顶部的系统 Header 内容，例如 View as a Web Page 链接区域。
- Footer：邮件底部的系统 Footer 内容，例如公司地址和退订链接。

具体可选值取决于账号的 IP 分配、产品设置和账户配置。

## 3. IP Address 配置概念

| 配置场景 | 说明 |
|---|---|
| Shared IP | 从共享 IP 池中自动选择，通常不能由用户指定具体地址 |
| Single Dedicated IP | 使用分配给账号的专用 IP |
| Multiple Dedicated IPs | 可按账号默认池或可选专用 IP 的配置方式使用 |

不能仅凭 Delivery Profile 名称判断实际发送 IP。需要结合账号的 IP 分配情况、Profile 配置和发送类型确认。

## 4. Header / Footer
### Header
通常指邮件文档顶部的系统 Header 内容，例如 View as a Web Page 链接。它不等同于模板中的品牌 Header 图片。

### Footer
通常包含组织邮寄地址和退订链接等内容。若 Delivery Profile 选择 None 或自定义 Library Content，必须确认邮件正文或自定义内容中包含适用的必要信息。

## 5. 实际操作：检查 Delivery Profile
1. 打开 Marketing Cloud Engagement Setup。
2. 在 Quick Find 中搜索 Delivery Profile。
3. 打开目标 Profile，记录 Name 和 External Key。
4. 检查 IP Address 的选择方式。
5. 检查 Header 和 Footer 的配置。
6. 确认关联的 Send Classification。
7. 通过测试发送检查邮件头、Footer、退订链接及实际投递行为。
8. 不要在生产环境中未经审批切换 IP 或 Footer 配置。

## 6. Sender Profile 与 Delivery Profile 的区别

| 项目 | Sender Profile | Delivery Profile |
|---|---|---|
| From Name | 是 | 否 |
| From Email Address | 是 | 否 |
| 发送 IP 选择 | 否 | 是 |
| Header | 否 | 是 |
| Footer | 否 | 是 |
| 主要目的 | 定义发件人信息 | 定义投递相关信息 |

## 7. 常见问题
**Q1：为什么选择了专用 IP，但实际发送 IP 不符合预期？**
检查账号 IP 分配、Delivery Profile 选择、Send Classification 类型以及发送实际使用的配置。必要时联系 Salesforce Support 确认账号 IP 池。

**Q2：Footer 选择 None 是否可以不放退订链接？**
不能直接这样理解。必须确保邮件正文或其他适用位置包含法规和平台要求的退订信息及邮寄地址。

**Q3：Delivery Profile 是否负责决定邮件发给谁？**
不是。受众由发送流程中的 Audience / Send Definition 决定。
