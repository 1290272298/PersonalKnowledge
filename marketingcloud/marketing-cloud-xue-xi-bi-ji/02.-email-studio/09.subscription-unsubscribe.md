# 09. Subscription / Unsubscribe

## 1. 学习目标
理解 Subscriber 与 Subscription 的关系，区分 All Subscribers 状态、Publication List 订阅状态以及不同范围的 Unsubscribe，能够在发送前确认用户是否允许接收对应邮件。

## 2. Subscriber 与 Subscription
Subscriber 是 Marketing Cloud Engagement 邮件发送体系中的订阅者记录。Subscriber 通常通过 Subscriber Key 识别。

Subscription 表示 Subscriber 对特定邮件类型或订阅主题的接收意愿。不能将 Subscriber 是否存在、All Subscribers 状态和某个 Publication List 的订阅状态视为同一件事。

## 3. All Subscribers 与 Subscriber Status

| Status | 含义（概念说明） |
|---|---|
| Active | 当前状态允许按适用规则发送 |
| Unsubscribed | 已退订 |
| Held | 由于退信等原因被暂停发送 |
| Bounced | 退信相关状态；实际界面和状态处理需结合账号行为确认 |

不要将 Held 与 Unsubscribed 混为一谈。Held 通常需要调查退信原因；Unsubscribed 则表示退订状态。

## 4. Publication List
Publication List 用于管理某一类邮件主题的订阅偏好，例如 Product News、Campaign Information、Monthly Newsletter 和 Event Information。

示例：

    Subscriber: C0001
    ├─ Product News: Subscribe
    ├─ Newsletter: Unsubscribe
    └─ Event Information: Subscribe

Publication List 可用于细分订阅管理，但发送时必须确认邮件、Send Classification 和 Publication List 的配置是否正确。

## 5. 不同退订范围

| 类型 | 影响范围（概念） |
|---|---|
| List Unsubscribe | 退订特定 List |
| Publication List Unsubscribe | 退订特定 Publication List |
| Universal Unsubscribe | 按账号/企业配置影响该组织范围内的邮件订阅 |
| Global Unsubscribe | 对 Marketing Cloud Engagement 平台范围内的邮件进行全局抑制 |

不同账号类型、Enterprise 结构和 Subscriber Filter 设置可能影响 Universal Unsubscribe 的范围。Global Unsubscribe 是平台级别的退订范围，不能简单等同于单个 BU 的退订。

## 6. Unsubscribe 后会发生什么
- Subscriber 通常不会因为退订而从数据列表或账号中被删除。
- 其 Subscriber 状态或相应订阅状态会发生变化。
- 后续发送是否被抑制，取决于退订范围、发送分类、Publication List 和账号设置。
- 不应通过导入或其他操作绕过用户的退订意愿。

Transactional 发送的处理可能与 Commercial 发送不同，但不能以 Transactional 为理由忽视用户意愿、Publication List 设置或适用法规。应按具体业务目的和账号配置确认。

## 7. 实际操作：检查 Subscriber 订阅状态
1. 在 Email Studio 打开 Subscribers / All Subscribers（菜单位置以账号为准）。
2. 使用 Subscriber Key 查找目标 Subscriber。
3. 检查当前 Status。
4. 如业务使用 Publication List，进一步检查对应订阅主题的状态。
5. 确认邮件发送时使用的 Send Classification 和 Publication List。
6. 在测试 BU 中验证退订行为。
7. 记录退订范围、发生时间、操作来源和验证结果。

## 8. 实际操作：设计退订测试
使用专用测试 Subscriber，准备至少以下场景：

| 测试对象 | 预期验证 |
|---|---|
| Active 且已订阅 Publication List | 确认正常发送条件 |
| Active 但已退订某 Publication List | 确认对应主题发送抑制 |
| All Subscribers 为 Unsubscribed | 确认全局/账号范围抑制行为 |
| Held | 确认发送抑制和排障路径 |

必须在测试环境中执行，不要通过真实用户账户验证退订行为。

## 9. 常见问题
**Q1：Unsubscribe 后 Subscriber 会被删除吗？**
通常不会。退订主要改变订阅状态，而不是删除 Subscriber 记录。

**Q2：Publication List 退订是否等于 All Subscribers 退订？**
不等于。Publication List 用于特定订阅主题；All Subscribers 的状态代表更广范围的 Subscriber 状态。

**Q3：为什么 Salesforce CRM 的 Email Opt Out 与 Marketing Cloud 状态不一致？**
Marketing Cloud Connect 的同步行为有特定操作要求。仅修改 CRM 的 Email Opt Out 字段不一定会同步更新 Engagement Subscriber 状态，应使用官方支持的 Marketing Cloud Unsubscribe / Resubscribe 操作并检查集成配置。

**Q4：Global Unsubscribe 能否由 BU 管理员直接重新激活？**
不能假设可以。Global Unsubscribe 有独立的平台级处理规则，重新激活需遵循 Salesforce 规定的流程。
