# 07. Send

## 1. 学习目标
理解 Email Studio 的发送流程，检查发送受众、Sendable Data Extension、Subscriber Key、发送分类和排除条件，并安全地完成测试发送与正式发送。

## 2. Send 是什么
Send 是将已准备好的 Email 发送给指定受众的执行过程。发送时不仅要选择邮件，还要确认受众、发送配置、订阅状态和发送时间。

- Email：发送什么内容。
- Audience：发送给谁。
- Send Classification：使用什么发送分类和配置。
- Send：执行发送。
- Tracking：记录发送后的事件。

## 3. 常见受众来源
- Sendable Data Extension
- List / Subscriber List
- Filtered Audience 或其他可用受众
- Journey Builder 中的 Email Activity（不是普通的手动 Send Flow）

不同发送入口支持的受众类型不同，不能将所有入口视为完全相同。

## 4. Sendable Data Extension
用于邮件发送的 DE 应正确配置 Sendable 设置和字段关系。

示例：

| 字段 | 类型示例 | 用途 |
|---|---|---|
| SubscriberKey | Text | Subscriber 标识 |
| EmailAddress | EmailAddress | 邮件地址 |
| FirstName | Text | 个性化字段 |
| MemberType | Text | 动态内容条件 |

检查重点：
1. SubscriberKey 是否唯一且稳定。
2. EmailAddress 字段是否正确配置。
3. Send Relationship 是否映射到正确的 Subscriber Key。
4. 个性化字段是否存在于发送数据中。
5. 数据是否存在重复、空值或无效邮箱。

对于 Sendable DE，系统会按 Subscriber Key 识别 Subscriber；使用 Subscriber Key 时，重复记录的处理不是简单按 Email Address 去重。

## 5. 发送前数据检查

| 检查项 | 检查内容 |
|---|---|
| 记录数 | 与预期目标数量是否一致 |
| Subscriber Key | 是否为空、重复或错误映射 |
| Email Address | 是否为空、格式是否有效 |
| 订阅状态 | 是否存在 Unsubscribed / Held 等状态 |
| 发送字段 | 个性化字段是否完整 |
| 排除条件 | 是否排除不应发送的对象 |
| Publication List | 是否选择了正确的订阅范围 |
| 测试数据 | 是否已覆盖空值、边界值和不同用户类型 |

## 6. Test Send 与正式发送

### Test Send
用于验证邮件内容、个性化和显示效果。测试前应确认测试地址、测试数据和测试目的。

建议至少覆盖：
- 字段完整的用户。
- 个性化字段为空的用户。
- 不同会员等级或业务分支。
- 桌面端与移动端显示。

Test Send 的执行逻辑和正式发送可能不同，不能只凭测试邮件成功就认定正式发送一定成功。

### 正式 Send
1. 选择正确的 Email。
2. 确认 Subject、Preheader 和 From 信息。
3. 选择目标 Audience。
4. 确认 Send Classification。
5. 检查排除对象、Publication List 和发送时间。
6. 预览发送对象数量及关键数据。
7. 执行最终审核。
8. 按审批流程立即发送或安排 Schedule。
9. 保存 Send ID / Job 信息，以便后续 Tracking 和排障。

## 7. 常见问题与排查方向

**Q1：为什么 DE 中有记录，但实际没有发送？**
检查 DE 是否 Sendable、Subscriber Key / EmailAddress 映射、Subscriber 状态、List Detective、排除条件和发送日志。

**Q2：为什么 DE 的 EmailAddress 与实际收件地址不一致？**
当 Subscriber 已存在于 All Subscribers 时，常规 Sendable DE 发送可能使用 All Subscribers 中已有的 Email Address。Salesforce Data Extension 等特定发送场景存在不同优先规则。必须结合发送类型确认，不能将单一规则套用到所有场景。

**Q3：为什么重复 Email Address 的记录表现不符合预期？**
当使用 Subscriber Key 时，去重逻辑可能基于 Subscriber Key，而不是 Email Address。检查业务主键、重复记录和发送受众设计。

**Q4：为什么 Test Send 成功但正式发送失败？**
正式发送还涉及受众规模、Subscriber 状态、发送权限、发送分类、排除条件和实际数据质量，应查看具体 Send Job 错误和 Tracking。

## 8. 实战练习：一次小规模测试发送
1. 创建专用测试 DE，准备 2～5 条测试记录。
2. 配置 Sendable Relationship。
3. 制作包含 FirstName 的测试邮件。
4. 检查 Subscriber Key、EmailAddress 和个性化字段。
5. 选择测试用 Send Classification。
6. Preview 并执行 Test Send。
7. 小范围正式发送到已授权的测试地址。
8. 记录 Send Job / Send ID。
9. 打开 Tracking，核对 Sent、Bounce、Open、Click 等事件。
10. 记录实际结果与预期差异。
