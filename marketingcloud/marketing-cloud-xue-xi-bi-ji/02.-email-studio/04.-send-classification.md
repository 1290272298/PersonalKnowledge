# 04. Send Classification

## 1. 学习目标
理解 Send Classification 的用途、组成和适用范围，能够解释它与 Sender Profile、Delivery Profile、Commercial / Transactional 分类之间的关系。

## 2. Send Classification 是什么
Send Classification 用于在集中位置定义邮件发送作业的一组参数，便于多个发送重复使用相同的发送配置。

主要包含：
1. Sender Profile
2. Delivery Profile
3. CAN-SPAM Classification（Commercial 或 Transactional）

Sender Profile 和 Delivery Profile 需要分别创建，再关联到 Send Classification。

## 3. 三个组成部分

| 组成 | 主要职责 | 关键问题 |
|---|---|---|
| Sender Profile | From Name、From Email 等发件人信息 | 收件人看到谁发送？ |
| Delivery Profile | IP 地址选择、Header / Footer 等投递信息 | 使用什么投递配置？ |
| CAN-SPAM Classification | 将发送定义为 Commercial 或 Transactional | 这次发送属于哪类邮件？ |

注意：API 对象模型中的 SendClassificationType 也可能使用 Marketing / Operational 等枚举概念。学习界面配置时，应以当前账号 UI 和官方对象文档为准，不要将不同 API 属性或产品界面的术语混为一谈。

## 4. Commercial 与 Transactional

### Commercial
通常用于推广、营销或促销类内容，例如新商品介绍、Campaign 优惠信息、Newsletter 和活动宣传。这类发送需要遵循适用的退订要求和公司合规规则。

### Transactional
通常用于用户请求或业务流程所需的通知，例如订单确认、密码重置和账户安全通知。

不能仅因为邮件标题写着“通知”就将其归类为 Transactional。分类应根据邮件的真实目的、内容和适用法规确定，并遵循公司法务及运营规则。

## 5. 配置关系

    Send
      ↓
    Send Classification
      ├─ Sender Profile
      │    └─ From Name / From Address
      ├─ Delivery Profile
      │    └─ IP / Header / Footer
      └─ Commercial / Transactional

在部分发送交互中，可能允许覆盖 Send Classification 中的 Sender Profile 或 Delivery Profile。应检查实际发送配置，避免以为选择分类后所有参数都不可变。

## 6. 实际操作：检查 Send Classification
1. 确认当前 BU 和操作权限。
2. 在 Setup 中查找 Send Classification。
3. 打开现有分类，记录 Name、Classification Type、Sender Profile 和 Delivery Profile。
4. 分别打开关联的 Sender Profile、Delivery Profile，确认配置内容。
5. 在测试发送中确认最终使用的分类及 From / Delivery 行为。
6. 不要直接修改生产默认分类；先确认依赖该分类的发送流程和项目影响。

创建分类前应先准备并确认 Sender Profile、Delivery Profile。

## 7. 项目设计建议
命名应能体现用途、BU 或发送场景，例如：
- SC_MKT_NEWSLETTER
- SC_MKT_CAMPAIGN
- SC_TXN_ORDER
- SC_TXN_SECURITY

这是命名建议，不是平台强制规则。不要仅按部门随意创建重复配置；应先盘点现有分类和依赖关系。

## 8. 常见问题
**Q1：Send Classification 是否等于 Sender Profile？**
不是。Send Classification 是组合配置，Sender Profile 只是其中一个组成部分。

**Q2：Transactional 是否可以不考虑退订？**
不能简单这样理解。Transactional 的适用性、Publication List 选择、订阅偏好处理和法规要求都需要按业务场景及账号设置确认。

**Q3：修改 Send Classification 会影响什么？**
可能影响所有使用该分类的发送定义或流程。修改前应检查依赖关系并安排测试。
