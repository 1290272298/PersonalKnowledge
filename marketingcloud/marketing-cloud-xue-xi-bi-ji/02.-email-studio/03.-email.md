# 03. Email

## 1. 学习目标
理解 Email 的组成、创建方式、个性化方式和发送前检查项目；能够制作一封可供测试的邮件。

## 2. Email 是什么
Email 是实际发送给 Subscriber 的邮件消息资产。它包含主题、预览文字、发件人相关设置、正文内容和适用的 Footer 等信息。

需要区分：
- **Email 内容资产**：定义邮件显示什么内容。
- **Send 配置**：定义使用什么发送配置以及发送给谁。
- **Send 执行**：真正启动或安排发送。

## 3. 邮件主要组成

| 项目 | 说明 | 检查重点 |
|---|---|---|
| Subject | 收件箱显示的邮件主题 | 内容准确、长度适合 |
| Preheader | 收件箱中主题后面的预览文字 | 不应与 Subject 简单重复 |
| From Name / Address | 收件人看到的发件人信息 | 与 Sender Profile 及域名认证策略一致 |
| Reply-To | 收件人回复时使用的地址 | 邮箱有效且有人处理 |
| Body | HTML / Text 邮件正文 | 内容、链接、布局、无障碍 |
| Footer | 公司信息、地址、退订等 | 满足适用法规和公司政策 |

发件人信息通常由 Sender Profile 提供，但实际发送入口可能允许覆盖部分属性。

## 4. 常见创建方式
- Template：使用既有模板制作。
- HTML：粘贴或编写自定义 HTML。
- Text Only：纯文本邮件（若账号启用）。
- Existing Email：从已有邮件资产继续创建。

不同创建方式支持的编辑能力和 Tracking 能力可能不同。例如，纯文本邮件无法嵌入 HTML Tracking Pixel，因此不能依靠 Open Pixel 获取打开数据。

## 5. 个性化方式

### 5.1 Personalization String
示例：

    こんにちは %%FirstName%% 様

当发送数据中存在对应字段时，可在邮件中显示收件人的名字。字段名必须与实际发送上下文中的字段匹配。

### 5.2 AMPscript
AMPscript 可用于根据发送上下文中的数据动态输出内容、执行条件判断或读取适用的数据源。

示例（仅为语法示意，实际字段和数据源需按项目调整）：

    %%[
    VAR @firstName
    SET @firstName = AttributeValue("FirstName")
    ]%%
    こんにちは %%=v(@firstName)=%% 様

不要在未确认字段来源、空值处理和数据权限时直接将示例用于生产邮件。

### 5.3 Dynamic Content
Dynamic Content 可根据预先配置的条件显示不同内容，例如按会员等级显示不同 Banner。必须为每个条件准备测试数据，并检查默认内容是否正确。

## 6. Email 与 Data Extension
邮件个性化通常依赖发送上下文中的字段。一个简单的 Sendable DE 示例：

| SubscriberKey | EmailAddress | FirstName | MemberType |
|---|---|---|---|
| C0001 | test1@example.com | Hanako | Gold |
| C0002 | test2@example.com | Taro | Silver |

需要注意：
- SubscriberKey 用于识别 Subscriber，不能随意用 Email Address 替代。
- 发送 DE 必须正确配置 Send Relationship / Sendable 字段。
- 个性化字段必须存在于实际发送上下文或可访问的数据源中。
- 目标 DE 中的 EmailAddress 与 All Subscribers 中已有地址的优先规则，可能因发送场景而不同；不要假设所有场景都采用相同逻辑。

## 7. 实际操作：制作一封测试邮件
1. 在 Content Builder 创建 Email Message。
2. 选择 Template 或 HTML 等创建方式。
3. 设置邮件名称、Subject 和 Preheader。
4. 添加标题、正文、图片、CTA 和 Footer。
5. 加入一个简单的 FirstName 个性化字段。
6. 准备至少两条测试数据：字段完整和字段为空。
7. 使用 Preview / Test Data 检查两种情况。
8. 检查链接、图片、移动端布局和退订链接。
9. 保存邮件，等待发送配置和受众准备完成后再执行 Test Send。

## 8. 常见问题
**Q1：为什么个性化字段没有显示？**
检查字段名称是否正确、字段是否在发送上下文中、是否存在空值，以及 AMPscript 是否有语法错误。

**Q2：为什么纯文本邮件没有 Open Tracking？**
纯文本没有 HTML，无法嵌入用于 Open Tracking 的像素。可结合 Click 等事件分析，但 Click 不能完全替代 Open。

**Q3：邮件保存后能否直接发送？**
保存只完成内容资产制作。还需要配置受众、发送分类和发送流程。

## 9. 学习 Checklist
- [ ] 能说明 Subject、Preheader、From、Body、Footer 的作用。
- [ ] 能区分 Email 内容和 Send 执行。
- [ ] 能使用 Personalization String 或 AMPscript 输出字段。
- [ ] 能测试字段为空时的显示。
- [ ] 能检查邮件在桌面端和移动端的效果。
