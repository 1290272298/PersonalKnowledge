# 06. List Detective

## 学习目标
理解 List Detective 的用途、可能拦截的地址类型，以及导入和发送前的检查方法。

## 1. 功能
List Detective 用于识别常见拼写错误、已知无效域名或风险地址，减少错误地址进入 Subscriber / Send 数据。它可在导入 Subscriber 数据或发送时对符合条件的数据进行检查；具体适用范围取决于导入方式和发送对象。

## 2. 常见识别情形
- 常见邮箱域名拼写错误
- 不存在或已知无效的域名
- 格式明显异常的地址
- 平台识别的其他风险地址

List Detective 不是完整的邮箱验证服务，也不能保证邮箱真实存在或用户有订阅许可。

## 3. 导入时注意
导入任务可能提供 List Detective 相关选项或处理结果。检查 Import Activity 的结果文件、错误/跳过数量和导入日志。不要只看最终 DE 行数。

## 4. 测试邮箱被拦截时
如果 Outlook / Gmail 等测试地址无法导入：
1. 检查地址是否有拼写、空格或隐藏字符。
2. 检查 Import Activity 的 List Detective 选项和结果。
3. 检查是否使用 Subscriber Import 还是 DE Import。
4. 确认目标字段类型和导入映射。
5. 用组织批准的测试地址验证，不要通过伪造域名或绕过检查来解决生产数据问题。

## 5. 常见误区
- List Detective 不等于邮箱是否存在的实时 SMTP 验证。
- 被跳过不一定意味着 DE 字段结构错误。
- 禁用检查会增加无效地址风险，必须经业务和管理员批准。

## Checklist
- [ ] 导入方式和 List Detective 设置明确
- [ ] 导入结果和跳过原因已检查
- [ ] 邮箱地址格式清理完成
- [ ] 测试地址来源合规
- [ ] 未将 List Detective 当作订阅许可检查
