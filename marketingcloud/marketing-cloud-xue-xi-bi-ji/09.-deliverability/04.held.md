# 04. Held

## 学习目标
理解 Held Subscriber 状态的意义、常见形成原因和安全处理方式。

## 1. Held 是什么
Held 是 Email Studio 中 Subscriber 的一种状态，表示该地址当前不应继续接收常规邮件发送。Marketing Cloud Bounce Management 会根据连续 Bounce 等规则将部分 Subscriber 置为 Held，以保护发送信誉。

## 2. 常见原因
- 地址持续产生永久或符合规则的 Bounce
- 邮箱/域名不可达或无效
- 接收方长期拒绝
- 历史发送产生持续失败

Held 不等同于 Unsubscribed。两者的业务含义和处理规则不同。

## 3. 排查步骤
1. 在 All Subscribers / Subscriber 记录中确认当前状态。
2. 查询最近发送记录和 Bounce Diagnostic。
3. 判断是地址错误、收件方问题还是发送信誉问题。
4. 确认地址已被用户/业务方验证有效。
5. 按组织的合规和运营流程处理状态，不要为了测试而批量恢复 Held。

## 4. Held 恢复注意
只有在确认地址有效、根因已修复并符合内部政策后，才评估是否恢复。恢复状态不代表后续一定成功投递，也不应覆盖 Unsubscribe 或其他抑制规则。

## 5. 常见问题
- 测试邮箱为 Held：检查测试地址历史 Bounce，不要反复重发。
- 状态恢复后仍未收到：检查发送资格、抑制、Bounce 和 Inbox Placement。
- Held 与退订混淆：分别查看 Subscriber Status 和退订记录。

## Checklist
- [ ] 当前 Subscriber Status 已确认
- [ ] Bounce 历史与原因已查明
- [ ] 地址有效性经过确认
- [ ] 恢复动作符合内部审批规则
- [ ] 未绕过 Unsubscribe / Suppression
