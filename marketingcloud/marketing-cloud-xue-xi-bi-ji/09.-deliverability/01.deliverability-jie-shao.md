# 01. Deliverability 介绍

## 学习目标
理解 Email Deliverability 的含义、影响因素和排查思路。

## 1. 什么是 Deliverability
Deliverability 指邮件能否被接收方邮件系统接受并投递到目标位置。需要区分：
- Sent：Marketing Cloud 处理/发送的记录。
- Delivered：接收服务器接受邮件，不代表一定进入 Inbox。
- Inbox Placement：邮件最终进入 Inbox、Promotion、Junk 或 Spam 等位置。
- Bounce：接收方拒绝或无法接受邮件。
- Complaint：收件人将邮件标记为垃圾邮件并产生投诉反馈。

## 2. 主要影响因素
- Sender Reputation：发送域名和 IP 的历史表现。
- Authentication：SPF、DKIM、DMARC。
- List Quality：地址有效性、来源、许可和活跃度。
- Engagement：用户互动和投诉/退订情况。
- Sending Pattern：发送量、频率和突然增长。
- Content / URL：内容、链接域名和风险信号。
- Recipient Policy：不同 ISP / 企业网关的过滤规则。

## 3. 诊断思路
先判断问题范围：
1. 单个收件人还是整个域名？
2. 仅某个 ISP（如 Outlook）还是多个 ISP？
3. 是 Bounce / Held，还是 Delivered 但进入 Spam？
4. 是否最近更换发送域名、IP、内容、链接或发送量？
5. SPF / DKIM / DMARC 是否正确对齐？

## 4. 常见误区
- Delivered 不代表 Inbox。
- 同一个发件域在不同 ISP 的结果可能不同。
- 邮件内容相同不代表发送信誉相同。
- 仅修改 SPF 不一定解决 DKIM / DMARC 或声誉问题。
- 不应通过更换地址、域名或重试绕过投诉和退订。

## Checklist
- [ ] 发送结果与 Inbox Placement 分开分析
- [ ] 发送域名和 IP 明确
- [ ] SPF / DKIM / DMARC 已验证
- [ ] 受众来源与许可可追踪
- [ ] 发送量和投诉/退订有基线
