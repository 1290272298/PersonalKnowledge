# 08. Deliverability 管理

## 学习目标
建立日常邮件送达率监控、问题分级、恢复和长期治理流程。

## 1. 日常监控
| 指标 | 监控目的 |
|---|---|
| Send / Delivered | 观察发送和接收服务器接受情况 |
| Hard / Soft Bounce | 识别无效地址和暂时性故障 |
| Block Bounce | 识别策略/信誉拒绝 |
| Held | 识别被抑制的地址 |
| Complaint | 监控用户垃圾邮件投诉 |
| Unsubscribe | 监控用户退订趋势 |
| Open / Click | 辅助观察互动（注意隐私代理和扫描影响） |

## 2. 问题分级
- 单个地址：优先检查拼写、邮箱状态和 Subscriber 历史。
- 单一 ISP：检查 ISP 响应、策略和域名/IP 信誉。
- 多个 ISP：检查发送配置、认证、内容和账号级信誉。
- Delivered 但进 Spam：重点检查 Inbox Placement、信誉、互动和内容，不要只看 Bounce。

## 3. 发送前治理
- 确认订阅来源和许可。
- 对新受众进行数据质量检查。
- 控制发送量增长和发送频率。
- 保持 From Domain、链接域和品牌一致。
- 确认 SPF / DKIM / DMARC。
- 对高风险或长期不活跃人群制定重新确认策略。

## 4. 故障处理流程
1. 暂停可能扩大影响的批量发送（按内部审批流程）。
2. 保存 Job、时间、受影响域名、SMTP Diagnostic 和样本。
3. 判断问题属于地址、内容、认证、信誉还是收件方策略。
4. 修复根因并验证 DNS / 配置。
5. 小范围测试，再逐步恢复发送。
6. 记录根因、影响范围和预防措施。

## 5. 联系支持时准备
提供 MID / BU（按支持要求）、Job ID、发送时间及时区、收件域、Bounce Diagnostic、测试样本和近期变更。不要在公开工单中提供密码、Client Secret 或完整个人数据。

## Checklist
- [ ] 每周/每月送达率报告
- [ ] 认证记录和域名状态定期复核
- [ ] 发送许可、投诉和退订持续治理
- [ ] ISP 问题有分类与负责人
- [ ] 故障恢复有小流量验证
- [ ] 事后复盘和防复发措施完成
