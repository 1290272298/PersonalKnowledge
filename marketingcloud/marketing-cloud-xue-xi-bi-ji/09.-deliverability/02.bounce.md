# 02. Bounce

## 学习目标
理解 Bounce 的含义、常见类型、对 Subscriber 状态的影响和排查方法。

## 1. Bounce 是什么
Bounce 表示接收方邮件服务器拒绝或无法接受邮件。Bounce 原因可能来自地址无效、邮箱不存在、邮箱满、接收方策略、认证或信誉等。

## 2. 常见类型
- Hard Bounce：永久性失败，例如地址不存在或域名无效。
- Soft Bounce：暂时性失败，例如邮箱满、服务器暂时不可用或临时策略限制。
- Block Bounce：邮件因接收方策略、信誉或内容等原因被阻止；具体分类取决于接收方返回信息和平台处理。

不要只看类型名称，需查看 Bounce Category、SMTP Response / Diagnostic Code 和接收方响应文本。

## 3. 排查步骤
1. 在 Tracking / Bounce 数据中定位 Job、Subscriber 和时间。
2. 读取 Bounce 分类和 SMTP Diagnostic Code。
3. 判断是否单地址、某 ISP 或全域问题。
4. 检查地址有效性、DNS、认证、域名/IP 声誉。
5. 修正根因后再决定是否允许后续发送。

## 4. 对 Subscriber 的影响
Marketing Cloud 会根据 Bounce Management 规则处理持续失败的地址。某些连续或特定 Bounce 会导致 Subscriber 状态变化，例如 Held。不要将所有 Soft Bounce 都理解为立即 Held，也不要未经检查手动恢复 Held。

## 5. 常见问题
- 某个地址一直 Bounce：确认地址拼写、域名和邮箱是否存在。
- 某 ISP 集中 Bounce：检查 ISP 策略、认证和 IP / Domain Reputation。
- SMTP 代码含糊：结合完整响应、发送时间和接收方文档判断。
- 修复后仍失败：确认状态、抑制、缓存和发送配置。

## Checklist
- [ ] 记录 Bounce Code / Category / Diagnostic
- [ ] 按 ISP 和域名聚合分析
- [ ] Hard / Soft / Block 分类正确
- [ ] 不对无效地址反复发送
- [ ] 根因修复后有小范围验证
