# 03. Block Bounce

## 学习目标
理解 Block Bounce 的典型含义，区分地址错误与接收方策略拒绝。

## 1. 什么是 Block Bounce
Block Bounce 通常表示接收方服务器或中间安全系统基于策略、信誉、认证、内容或流量模式拒绝邮件。不同 ISP 返回的 SMTP Diagnostic 不同，平台的分类也依赖接收方响应。

## 2. 常见原因
- 发送 IP 或域名信誉较差
- SPF / DKIM / DMARC 认证或对齐问题
- 发送量突然增加或异常频率
- URL / 跟踪域名被安全策略拦截
- 内容或附件触发接收方过滤
- 企业邮件网关策略拒绝

## 3. 排查步骤
1. 收集完整 Bounce Diagnostic / SMTP Code。
2. 按收件域名聚合，判断是否集中于某 ISP。
3. 检查发件域、DKIM 签名域和 SPF 授权。
4. 检查 DMARC 对齐和 DNS 记录。
5. 检查 IP / Domain Reputation、发送量和内容链接。
6. 必要时联系接收方 Postmaster / IT 管理员，并向 Salesforce Support 提供样本。

## 4. 与 Hard Bounce 的区别
Hard Bounce 通常指永久性地址/域名问题；Block Bounce 更偏向策略性拒绝。实际分类需以 SMTP Diagnostic 为准，不应只凭平台状态字段推断根因。

## 5. 注意事项
不要通过不断更换 From Domain、IP 或重复发送来规避阻止。应先查明原因，确认修复后逐步恢复发送。

## Checklist
- [ ] 完整 SMTP Diagnostic 已保存
- [ ] 受影响 ISP / Domain 已识别
- [ ] 认证和信誉已检查
- [ ] 内容、链接和发送量已检查
- [ ] 恢复发送有验证和审批
