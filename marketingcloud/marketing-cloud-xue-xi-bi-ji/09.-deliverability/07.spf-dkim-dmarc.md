# 07. SPF / DKIM / DMARC

## 学习目标
理解 SPF、DKIM 和 DMARC 的作用、对齐关系及 Marketing Cloud 发件域名配置注意事项。

## 1. SPF
SPF 通过 DNS TXT 记录声明哪些发送服务器可代表某个域发送邮件。配置时应由域名管理员根据实际发送平台提供的值维护。一个域名通常应避免发布多个互相冲突的 SPF 记录；多个发送来源需合并到同一 SPF Policy。

## 2. DKIM
DKIM 使用域名私钥对邮件签名，收件方通过 DNS 中的公钥验证签名。Marketing Cloud 的 Sender Authentication Package / 域名认证配置会提供相应的 DKIM 设置。需确认邮件实际使用的签名域和 DNS 记录已正确发布。

## 3. DMARC
DMARC 定义收件方如何处理 SPF / DKIM 未通过或未对齐的邮件，并提供报告机制。DMARC 对齐检查 From Header 域与 SPF / DKIM 身份域是否符合策略。建议先从监控策略评估，再逐步收紧策略，避免影响合法业务邮件。

## 4. 三者关系
| 技术 | 解决的问题 |
|---|---|
| SPF | 哪些服务器被授权代表域名发送 |
| DKIM | 邮件是否具有该域的有效数字签名 |
| DMARC | SPF / DKIM 结果是否与 From 域对齐，以及失败处理策略 |

SPF 或 DKIM 单独通过，不代表 DMARC 一定通过；还需要检查对齐模式和 From Domain。

## 5. Marketing Cloud 配置检查
1. 确认使用的 From Domain / Sender Domain。
2. 从 Salesforce / SAP 配置取得所需 DNS 记录。
3. 由域名管理员发布 TXT / CNAME 等记录。
4. 使用 DNS 查询工具验证记录已生效。
5. 发送测试邮件，检查邮件头 Authentication-Results。
6. 验证 SPF、DKIM、DMARC 的 pass / alignment。
7. 监控 DMARC Aggregate Reports。

不要直接复制其他账号的 DNS 记录；每个域名和账号配置可能不同。

## 6. 常见问题
- SPF PermError：检查重复 SPF TXT、语法和 DNS Lookup 限制。
- DKIM fail：检查 selector、CNAME/TXT、公钥发布和签名域。
- DMARC fail：检查 From 域对齐、SPF/DKIM 认证和 DMARC Policy。
- 认证通过但进 Spam：还需检查声誉、投诉、内容、发送量和收件方策略。

## Checklist
- [ ] From Domain 与认证域已盘点
- [ ] SPF 记录唯一且包含合法发送源
- [ ] DKIM selector / 公钥正确
- [ ] DMARC 对齐和 Policy 明确
- [ ] 测试邮件头已验证
- [ ] DNS 变更有审批和回退方案
