# 01. Subscriber / Subscription

## 案例 1：Subscriber 状态为 Held，测试邮件无法发送

- 状态：排查模板（具体实例需按实际证据确认）
- 影响：特定 Subscriber 无法接收常规邮件

### 问题
测试地址在发送时未收到邮件，Subscriber 状态显示 Held。

### 现象
All Subscribers 中可看到 Held 状态；发送记录中可能存在 Bounce 记录。

### 调查过程
1. 确认 Subscriber Key 和 Email Address。
2. 查看当前 Subscriber Status。
3. 查询最近发送记录及 Bounce Category / SMTP Diagnostic。
4. 判断是否为地址无效、接收方拒绝或持续 Bounce。
5. 检查是否同时存在 Unsubscribe 或其他 Suppression。

### 原因
Held 通常与 Bounce Management 对持续失败地址的处理有关。具体原因必须以 Bounce 记录和诊断码为准，不能仅凭 Held 状态判断地址不存在。

### 解决方案
先确认地址有效性并修复根因，再按组织的管理流程评估是否恢复状态。不要为了测试批量恢复 Held，也不要绕过退订状态。

### 注意事项
Held 与 Unsubscribed 含义不同；恢复 Held 不代表后续一定投递成功。

## 案例 2：导入时测试邮箱被 List Detective 跳过

### 调查重点
- 检查导入方式和 List Detective 选项。
- 检查 Import Results 中的跳过/错误记录。
- 确认邮箱地址格式、空格和隐藏字符。
- 区分 Subscriber Import 与 Data Extension Import。

### 结论
List Detective 是地址质量检查机制，不是实时邮箱存在性验证，也不能替代订阅许可检查。

## Checklist
- [ ] Subscriber Key 与 Email Address 分别确认
- [ ] Held / Unsubscribed 状态分开判断
- [ ] Bounce Diagnostic 已查看
- [ ] 导入结果和 List Detective 设置已确认
- [ ] 未绕过退订或抑制规则
