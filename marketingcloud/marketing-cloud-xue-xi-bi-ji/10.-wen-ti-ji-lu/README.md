# 10. 问题记录

本章用于将 Marketing Cloud 学习和项目排障经验整理为可复用知识。问题记录不是单纯写“原因和解决方法”，而是保留现象、证据、排查步骤、结论可信度和防复发措施。

## 问题记录标准模板
```markdown
# 问题标题

- 状态：未调查 / 调查中 / 已解决 / 已知限制
- 产品 / BU：填写必要范围，不写敏感账号信息
- 发生时间：YYYY-MM-DD HH:mm（含时区）
- 影响范围：人数、DE、Automation、Journey、Job 等
- 环境：测试 / 生产

## 1. 问题
描述希望实现的行为与实际差异。

## 2. 现象
记录原始错误信息、状态、截图/日志位置和复现步骤。

## 3. 调查过程
按时间记录每一步确认、结果和排除项。

## 4. 原因
区分已确认根因、推测原因和仍待确认事项。

## 5. 解决方案
记录变更内容、执行步骤、验证结果和回退方式。

## 6. 结论
用简短语言总结可复用知识。

## 7. 注意事项 / 防复发
监控、权限、数据校验、重试和变更管理。
```

## 记录规则
- 不把推测写成已确认根因；没有证据时标记“待确认”。
- 记录产品版本、BU/MID 上下文、发生时间及时区。
- 错误信息可保留必要技术内容，但必须脱敏 Client Secret、Token、邮箱、手机号、客户 ID 等个人/凭证信息。
- 解决方案应有验证结果，必要时记录回退方案。
- 同一问题重复发生时，关联历史记录并说明本次差异。
- 外部平台或 Salesforce 产品行为可能变化，附官方文档和查阅日期。

## 问题处理流程
```
发现问题 → 保存证据 → 确定影响范围
    ↓
复现 / 排除 → 确认根因或标记未知
    ↓
修复 / 回退 → 验证
    ↓
记录结论 → 监控防复发
```

## 上线前 Checklist
- [ ] 现象和预期描述清楚
- [ ] 原始日志/错误码已脱敏保存
- [ ] 已区分事实、推测和未知
- [ ] 根因有证据支持
- [ ] 修复有验证结果
- [ ] 防复发措施和负责人明确
