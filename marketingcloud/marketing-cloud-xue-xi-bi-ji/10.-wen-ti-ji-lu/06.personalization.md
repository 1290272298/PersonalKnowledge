# 06. Personalization

## 案例 1：FTP 导入用户数据，只更新部分字段

### 问题
已有 User 数据包含字段 A、B、C；本次导入文件只有主键 D 和字段 E。需要确认原有字段 C 是否会被清空。

### 调查过程
1. 确认导入对象、数据集和主键字段。
2. 确认导入模式是 Insert、Update、Upsert 或产品支持的其他模式。
3. 检查字段映射和未提供字段的处理规则。
4. 在测试数据集中准备一条含 A/B/C 的记录。
5. 仅导入主键和 E，随后读取该记录，比较 A/B/C/E。
6. 检查导入日志和失败记录。

### 原因
不能仅凭“文件没有字段 C”就判断 C 一定保留或一定清空。字段缺失语义取决于 Personalization 的导入模式、映射和更新机制，必须通过当前配置验证。

### 解决方案
将验证结果记录为当前数据集和导入方式的行为；生产导入前备份或导出样本，并明确字段缺失、显式空值和未映射字段的区别。

## 案例 2：管理员权限变更后无法查看数据集
### 调查重点
- 确认用户在 Marketing Cloud Engagement 与 Personalization 的账号关联。
- 检查 Personalization 用户角色和每个 Dataset 的访问权限。
- 区分平台管理员权限与 Dataset 数据权限。
- 比较变更前后的角色、权限和报错信息。
- 按最小权限原则恢复所需访问，而不是无差别扩大权限。

### Checklist
- [ ] 导入模式和字段映射已确认
- [ ] 部分字段更新行为已在测试数据验证
- [ ] 原始数据有备份/回退方式
- [ ] Dataset 权限单独检查
- [ ] 账号角色变更有记录
