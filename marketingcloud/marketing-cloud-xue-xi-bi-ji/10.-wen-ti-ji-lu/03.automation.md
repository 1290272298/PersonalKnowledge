# 03. Automation

## 案例 1：Automation Studio 定时运行时 Activity 报错

- 状态：排查模板
- 现象：前一天正常，次日定时执行时第一步 Activity 失败。

### 问题
Automation 的第一步 Activity 在 Scheduled Run 中报错，手动执行与定时执行结果可能不同。

### 调查过程
1. 在 Automation Studio 打开 Run History，确认失败时间、Step 和 Activity。
2. 打开 Activity 详情，记录完整错误文本。
3. 确认失败是否发生在第一步，是否有前置文件或 DE 更新。
4. 检查依赖的 Data Extension、Import Definition、File Transfer、过滤列表或外部文件。
5. 检查数据量、文件名、权限、自动更新设置和最近配置变更。
6. 对比前一天成功运行时的输入文件、记录数和配置。

### 原因
在没有 Activity 错误详情前，不应直接归因于 Schedule。第一步失败通常需要优先检查该 Activity 自身及其依赖。

### 解决方案
根据错误定位修复数据源、文件、权限或 Activity 配置；先用安全的测试输入验证，再恢复定时执行。

### 注意事项
不要直接重复运行整个 Automation，尤其是包含发送、覆盖目标 DE 或文件移动步骤时。先判断前一次是否已产生部分副作用。

## 案例 2：SQL Query Activity 执行失败
检查 Source / Target DE、字段名、主键、Data Action、SQL 语法、数据量、并发和执行时长。

## 案例 3：File Transfer / Import 失败
检查 Safehouse 文件、文件名匹配、压缩/加密、UTF-8 编码、字段映射、导入模式和文件是否已被移动。

## Checklist
- [ ] Run History 与错误文本已保存
- [ ] 明确失败 Step / Activity
- [ ] 检查输入数据和前置依赖
- [ ] 重跑前确认是否有部分执行结果
- [ ] 修复后验证记录数和下游影响
