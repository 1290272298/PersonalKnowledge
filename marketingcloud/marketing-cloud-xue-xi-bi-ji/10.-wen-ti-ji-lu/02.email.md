# 02. Email

## 案例 1：邮件发送后 Outlook / 企业网关进入 Spam

- 状态：排查模板
- 现象：相同业务内容在不同收件方的投递位置不同。

### 问题
发往 Outlook 或企业安全网关的邮件进入 Junk / Spam，而其他域名收件正常。

### 调查过程
1. 确认是 Bounce、Delivered 但进 Spam，还是被企业网关隔离。
2. 收集 Job ID、发送时间、收件域和邮件头。
3. 检查 SPF、DKIM、DMARC 及 From Domain 对齐。
4. 检查 IP / Domain Reputation、发送量、内容链接和跟踪域。
5. 比较正常收件与异常收件的 Authentication-Results 和 SMTP Diagnostic。

### 原因
不能仅凭“Outlook 进 Spam”断定是 SPF 或 DKIM。还需评估信誉、内容、收件方策略和企业网关规则。

### 解决方案
根据证据修复认证、域名、内容或发送节奏；若是企业网关策略，需由收件方管理员确认。修复后小范围验证，再逐步恢复。

### 注意事项
Delivered 不等于 Inbox Placement。不要通过更换发件域名或反复发送规避过滤。

## 案例 2：Journey Email Activity 到达但未收到邮件

### 调查过程
1. 查看 Contact 是否到达 Email Activity。
2. 检查 Subscriber Status、Held、Unsubscribe 和 Suppression。
3. 检查 Email、Send Classification、Sender Profile、Delivery Profile。
4. 查看发送 Job / Tracking，而不是只检查收件箱。
5. 检查动态内容和发送上下文。

### Checklist
- [ ] 区分 Bounce 与 Spam Folder
- [ ] 保存邮件头和诊断码
- [ ] SPF / DKIM / DMARC 与声誉均检查
- [ ] 发送资格与消息配置检查
- [ ] 修复后有小流量验证
