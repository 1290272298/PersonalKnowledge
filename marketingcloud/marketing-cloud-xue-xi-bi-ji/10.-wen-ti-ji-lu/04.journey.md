# 04. Journey

## 案例 1：Contact 未进入 Journey

### 问题
入口 DE 中存在记录，但 Journey 中未观察到 Contact 进入。

### 调查过程
1. 确认 Journey 对应版本是否已 Activate。
2. 检查 Entry Source、Entry Event 和入口筛选。
3. 检查 DE 的 Sendable Relationship / Contact Key。
4. 若为 API Event，检查 Event Definition Key、请求响应和事件字段。
5. 检查 Re-entry 规则和 Contact 是否仍在同一 Journey 中。
6. 查看 Journey History / Contact History。

### 常见原因
- Journey 未激活或入口配置不匹配。
- Contact Key 为空或映射不一致。
- 入口条件不满足。
- API Event 没有成功触发。
- Re-entry 策略不允许再次进入。

## 案例 2：Decision Split 分支与预期不一致
检查 Journey Data / Contact Data、Contact Model 关系、字段更新时间、空值、字段类型和条件顺序。Decision Split 多条件按路径顺序评估，先匹配的路径优先，未匹配时进入 Remainder。

## 案例 3：Contact 停留在 Wait
检查 Wait 时长、进入时间、时区、夏令时和 Journey 状态。确认是否存在 Goal / Exit Criteria 评估，以及后续 Activity 是否已经触发。

## 案例 4：Contact 重复进入
检查 Contact Key、Event ID、API 重试、入口数据重复和 Re-entry 配置。

## Checklist
- [ ] Journey Version 和状态明确
- [ ] Contact Key / Event ID 可定位
- [ ] Entry / Split / Wait 逐节点检查
- [ ] 发送副作用确认后才重试
- [ ] 记录在途 Contact 和版本影响
