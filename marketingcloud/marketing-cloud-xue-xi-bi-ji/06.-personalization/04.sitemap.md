# 04. Sitemap

## 学习目标
理解 Sitemap 的作用、页面类型、事件采集、身份识别和部署验证。

## 1. Sitemap 是什么
Personalization Sitemap 是实现 Web Channel 数据采集与个性化的 JavaScript 配置。它识别网站页面类型、用户交互、商品/内容对象和身份信息，为 User Profile、Catalog、分析和 Web Campaign 提供数据基础。

## 2. Sitemap 的职责
- 识别 Page Type（例如 Home、Category、Product、Cart、Order Confirmation）。
- 采集 Page View、View Item、Add to Cart、Purchase 等事件。
- 识别用户身份及登录状态变化。
- 将网站对象与 Catalog 对象关联。
- 定义可展示个性化内容的 Content Zone。

## 3. 页面类型设计
| Page Type | 典型事件/数据 |
|---|---|
| Home | Page View、推荐区 |
| Category | Category ID、商品列表 |
| Product | Product ID、价格、库存 |
| Cart | Cart Item、Quantity |
| Confirmation | Order ID、Revenue、购买商品 |

应根据网站实际 DOM、URL 规则和页面模板定义，不应只依赖易变的 CSS Selector。

## 4. 实施流程
1. 梳理网站页面类型和关键交互。
2. 定义事件、字段和 Catalog ID 映射。
3. 配置 Sitemap JavaScript。
4. 在开发/测试环境部署 SDK 和 Sitemap。
5. 验证 Page Type、事件 payload、身份和 Catalog 匹配。
6. 观察重复事件、缺失事件和页面性能。
7. 经业务/隐私审批后部署生产。

## 5. 身份和隐私
登录后发送已知用户身份时，应遵守隐私政策、Cookie Consent 和数据最小化原则。不要在事件 payload 中发送密码、访问令牌、支付卡号或不必要的敏感数据。跨设备身份合并必须有明确授权和业务规则。

## 6. 常见问题
- 页面类型识别错误：检查 URL、DOM 条件和加载时机。
- 事件重复：检查 SPA 路由切换、事件监听重复注册和页面重新渲染。
- 商品事件无法关联：检查 Product ID 与 Catalog ID。
- 登录后身份不一致：检查匿名/已知身份关联、登录登出事件和 Cookie 行为。

## Checklist
- [ ] 页面类型覆盖关键模板
- [ ] 事件字段和 Catalog ID 一致
- [ ] SPA 页面路由已验证
- [ ] 身份与 Consent 逻辑已确认
- [ ] 无敏感凭证进入事件 payload
- [ ] 页面性能与错误日志通过
