# 02. Data Model

## 学习目标
理解 Personalization 的用户、事件和 Catalog 数据，并设计可持续的数据模型。

## 1. 数据模型概念
Personalization 会基于用户身份、用户属性、行为事件和 Catalog 对象形成个性化上下文。具体字段和对象类型由数据集配置及产品能力决定。

常见数据类别：
- User：访客身份、已知用户 ID、用户属性。
- Event：Page View、View Item、Add to Cart、Purchase 等行为。
- Catalog Object：商品、文章、类别或其他可推荐实体。
- Transaction / Order：购买及交易相关信息（按数据模型设计）。
- Campaign / Experience：个性化展示与互动相关数据。

## 2. 用户身份
常见身份场景：
- Anonymous Visitor：尚未识别为登录用户的浏览器/设备访客。
- Known User：通过业务系统提供的稳定用户 ID 识别的用户。
- Identity Alias：在满足配置规则时，将匿名身份与已知身份关联。

身份设计要明确跨设备、登录、退出、共享设备和 Cookie 清理后的行为。不要把 Email、手机号等敏感或可变信息未经评估直接作为身份主键。

## 3. 事件设计
事件应包含明确的事件类型、时间、用户上下文及业务实体 ID。示例：
| 事件 | 关键字段 |
|---|---|
| View Product | Product ID、Category |
| Add to Cart | Product ID、Quantity、Price |
| Purchase | Order ID、Product ID、Revenue |
| Login | Known User ID / Identity |
| Page View | Page Type、URL / Content ID |

字段名称、类型和大小写应与 Sitemap、数据导入和 Catalog 保持一致。

## 4. 数据导入与更新
外部用户数据或 Catalog 数据可通过产品支持的数据导入机制、API 或集成导入。实施前确认：
- 唯一 ID 与 Upsert / 更新语义
- 字段缺失时是保留、清空还是默认值
- 时间戳时区与格式
- 数据集和环境
- 导入失败、重复数据和增量更新机制

不能仅凭“本次文件没带某字段”就推断该字段一定被清空；必须核实具体导入映射和更新模式。

## 5. 数据质量
定期检查身份重复率、事件缺失、Catalog ID 匹配率、无效时间戳和异常价格/库存。对关键事件建立数量基线。

## Checklist
- [ ] 用户身份及匿名转已知规则明确
- [ ] Event schema 已定义
- [ ] Catalog ID 与事件实体 ID 一致
- [ ] 导入的 Upsert / 字段缺失行为已验证
- [ ] 时间、时区和重复数据策略明确
