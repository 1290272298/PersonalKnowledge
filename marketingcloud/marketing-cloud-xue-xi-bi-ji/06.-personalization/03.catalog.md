# 03. Catalog

## 学习目标
理解 Catalog 的用途、对象类型、字段规范和更新流程。

## 1. Catalog 是什么
Catalog 是 Personalization 中保存可用于推荐和个性化的业务对象数据集合。常见对象包括商品、内容、类别、文章或服务。Catalog 对象可与用户行为事件关联，帮助系统理解用户浏览或购买了什么。

## 2. 关键字段
| 字段 | 用途 | 设计建议 |
|---|---|---|
| ID | 对象唯一标识 | 稳定、唯一，与事件 ID 一致 |
| Name | 展示名称 | 便于运营识别 |
| URL | 对象落地页 | 使用可访问的规范 URL |
| Image URL | 图片 | 使用稳定、可访问资源 |
| Category | 分类 | 统一编码和层级 |
| Price | 价格 | 数值类型和币种明确 |
| Availability | 库存/可用状态 | 更新频率符合业务要求 |

实际字段由数据集 Catalog schema 决定，不同 Catalog Object 类型可有不同属性。

## 3. Catalog 与 Event
当用户触发 View Item / Purchase 等事件时，事件中的对象 ID 应能匹配 Catalog ID。若 ID 不一致，可能造成行为无法正确关联到 Catalog 对象，影响推荐和分析。

## 4. 导入与更新
1. 明确 Catalog Object 类型和唯一 ID。
2. 设计字段 schema、数据源和更新频率。
3. 先导入少量测试记录。
4. 检查 ID、字段类型、URL 和图片资源。
5. 执行完整导入并监控错误。
6. 验证事件与 Catalog 对象是否正确关联。

## 5. 常见问题
- 对象未显示：检查导入是否成功、数据集、对象类型和 ID。
- 事件未关联对象：检查 Sitemap 事件 ID 与 Catalog ID。
- 图片/链接不显示：检查资源是否公开可访问、是否 HTTPS。
- 价格或库存陈旧：检查源系统更新频率和增量同步。

## Checklist
- [ ] Catalog Object 类型正确
- [ ] ID 唯一且与事件一致
- [ ] 字段类型、币种和时间规则明确
- [ ] 图片和 URL 可访问
- [ ] 导入失败和更新延迟可监控
