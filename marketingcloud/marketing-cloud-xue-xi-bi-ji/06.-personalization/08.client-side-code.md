# 08. Client-side Code

## 学习目标
理解客户端 Sitemap / SDK 代码的运行环境、数据采集、身份安全和性能治理。

## 1. 客户端代码职责
客户端代码通常负责初始化 Personalization SDK、执行 Sitemap 配置、识别页面类型、采集用户交互、传递事件和渲染 Web Campaign。服务端数据导入/API 则用于补充客户端无法可靠提供的数据。

## 2. 安全原则
- 不在浏览器代码中放置 Client Secret、API Secret、密码或长期访问令牌。
- 仅发送实现业务目的所需字段。
- 对用户身份和行为数据遵循 Consent / Cookie Policy。
- 不将支付卡号、密码、认证 Token 等敏感信息写入事件。
- 生产环境采用受控部署和版本管理。

## 3. 性能原则
- 避免阻塞首屏渲染。
- 避免重复初始化 SDK 和重复注册事件。
- 对 SPA 路由切换进行专门测试。
- 控制事件数量和 payload 大小。
- 避免高频 DOM 查询与 Mutation Observer 造成性能负担。
- 为异步页面组件定义稳定的加载时机。

## 4. 调试步骤
1. 确认 SDK 加载成功。
2. 检查 Sitemap 初始化与环境配置。
3. 检查页面类型识别。
4. 检查事件 payload、身份和 Catalog ID。
5. 检查 Campaign / Content Zone 响应。
6. 查看浏览器 Console、Network 和产品侧事件调试工具。
7. 比较开发、测试和生产配置差异。

## 5. 常见问题
- 事件重复：检查初始化是否重复、SPA route listener 是否多次绑定。
- 事件缺失：检查页面加载顺序、Consent、网络请求和 JS 异常。
- 用户身份错误：检查登录登出流程和匿名身份关联。
- 页面变慢：检查 SDK 加载方式、事件量、DOM 操作和模板脚本。

## Checklist
- [ ] SDK 初始化唯一
- [ ] SPA 路由与异步 DOM 已验证
- [ ] 事件 payload 不含敏感凭证
- [ ] Consent / 隐私规则符合要求
- [ ] 首屏性能和脚本错误已测试
- [ ] 代码部署有版本和回退机制
