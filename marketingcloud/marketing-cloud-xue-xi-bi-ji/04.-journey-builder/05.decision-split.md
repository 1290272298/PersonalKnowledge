# 06. Decision Split

## 学习目标
理解 Decision Split 如何根据数据属性分流，掌握 Journey Data / Contact Data、条件顺序和 Remainder 路径。

## 1. 功能
Decision Split 根据 Contact 到达节点时可用的数据和过滤条件，将 Contact 分配到对应路径。它回答的是“当前数据符合什么条件”，不是判断客户是否打开邮件。

## 2. 数据来源
- Journey Data：本次入口或活动上下文，如本次订单金额。
- Contact Data：Contact Model 中与 Contact 关联的属性，如会员等级。
判断前要明确字段来源、更新时间、关联关系和空值行为。

## 3. 条件顺序
多个路径按配置顺序评估。若 Contact 同时满足多个路径条件，会进入首先匹配的路径；未满足任何路径则进入 Remainder。路径顺序因此属于业务逻辑的一部分。

## 4. 示例
```
Decision Split
 ├─ VIP = true       → VIP Message
 ├─ OrderAmount >= X → High Value Message
 └─ Remainder        → Standard Message
```
若 VIP 客户同时满足金额条件，先匹配的 VIP 路径会优先，需按业务预期调整顺序。

## 5. 配置步骤
1. 添加 Decision Split。
2. 选择 Journey Data 或 Contact Data。
3. 选择字段、运算符和值。
4. 配置路径名称和顺序。
5. 明确 Remainder 路径的后续动作。
6. 用满足单一条件、多个条件、无条件、空值等测试数据验证。

## 6. 常见问题
- **结果与预期不一致**：字段数据源选错，或条件顺序导致先匹配其他分支。
- **找不到字段**：检查入口字段是否带入 Journey，或 Contact Builder 关系是否正确。
- **所有人进入 Remainder**：检查数据类型、空值、大小写、日期时区及比较运算符。
- **Contact Data 是旧值**：检查数据同步/更新时点，不要将入口快照当作实时主档。

- [ ] 数据源选择正确
- [ ] 条件顺序符合优先级
- [ ] 字段类型和空值逻辑已测试
- [ ] Remainder 路径已设计
- [ ] 使用真实代表性样本验证
