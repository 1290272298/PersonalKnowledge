# 01. Journey Builder 介绍

## 学习目标
理解 Journey Builder 的定位、核心对象、典型流程，以及它与 Automation Studio、Email Studio 的边界。

## 1. 产品定位
Journey Builder 是 Marketing Cloud Engagement 中用于编排客户跨时间、跨渠道互动的工具。它根据入口事件、Contact 数据和互动行为，让不同 Contact 沿不同路径执行消息发送、等待、判断和数据更新。

**核心对象是 Contact 的旅程状态，而不是单纯的数据批处理。**

## 2. 基本组成
```
Entry Source / Event
        ↓
     Contact
        ↓
     Activity
        ↓
  Split / Wait / Message
        ↓
  Goal / Exit / End
```
每个 Contact 的执行位置可以不同：A 可能正在等待，B 已到达 Email Activity，C 已退出。Journey 是持续运行的编排，而不是所有人同时执行的一次性流程。

## 3. 典型场景
- 欢迎旅程：注册事件 → 欢迎邮件 → 等待 → 新手指南
- 购买培育：进入候选人群 → 按客户等级分支 → 发送不同内容
- 购买后跟进：订单完成 → 等待 → 使用说明 → 满意度调查
- 行为触发：API Event → 事件确认 → 后续提醒

## 4. 与其他 Studio 的区别

| 工具 | 主要职责 | 典型对象 |
|---|---|---|
| Journey Builder | 编排 Contact 的客户旅程 | Contact、Event、Activity |
| Automation Studio | 按计划或触发执行数据处理任务 | Automation、SQL、Import、Extract |
| Email Studio | 创建、管理和发送邮件 | Email、Subscriber、Send |
| Contact Builder | 组织 Contact 数据与关系 | Contact Key、Attribute Group |

常见组合：Automation Studio 先整理数据，Journey Builder 根据入口和条件编排旅程，Email Studio 提供邮件内容与发送配置。

## 5. 设计边界
- Journey Builder 不替代复杂 ETL；大量数据清洗、汇总和去重通常先在 Automation Studio 完成。
- Entry Source 不是简单的“筛选器”；不同入口的触发方式和数据时点不同。
- Journey 的分支判断依赖数据关系和字段可用性，不能只看字段在某个 DE 中存在。
- 具体可用 Activity、渠道和 CRM 集成功能取决于账号许可、配置和产品版本。

## 6. 操作流程
1. 明确业务目标、目标人群和退出条件。
2. 确认 Contact Key 和入口数据结构。
3. 选择 Entry Source / Event。
4. 添加 Activity、分支和等待。
5. 配置 Goal、Exit Criteria、Journey Settings。
6. Validate、Test，确认测试 Contact 的路径。
7. Activate 后持续监控入口、Activity 和发送结果。

## 常见问题
**Journey Builder 是否等于 Automation？** 不是。Automation 负责数据/任务编排，Journey 负责 Contact 的互动旅程。

**一个 Journey 中所有 Contact 是否同步执行？** 不是。每个 Contact 独立推进，进入时间和活动耗时不同。

## Checklist
- [ ] 业务目标与人群定义清楚
- [ ] 数据处理和客户旅程职责分离
- [ ] Contact Key 与入口字段确认
- [ ] Activity、退出和监控方案已设计
