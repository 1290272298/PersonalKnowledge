# 05. Activities

## 学习目标
了解 Journey Canvas 中 Activity 的类别、执行顺序、输入输出和发布前验证方法。

## 1. Activity 是什么
Activity 是 Journey 中执行的动作或流程控制节点。常见类别包括 Messages、Flow Control、Customer Updates、Sales & Service Cloud 及 Custom Activities；具体类别和可用项目取决于账号配置。

## 2. 常见类别
| 类别 | 示例 | 作用 |
|---|---|---|
| Messages | Email、SMS、Push | 向 Contact 发送消息 |
| Flow Control | Wait、Decision Split、Engagement Split、Random Split、Join | 控制执行时间和路径 |
| Customer Updates | Update Contact | 更新 Contact 属性 |
| Sales & Service Cloud | CRM 相关 Activity | 与已连接的 CRM 数据交互 |
| Custom | 自定义 Activity | 执行扩展集成逻辑 |

## 3. Activity 执行逻辑
Contact 到达 Activity 后，按该节点的配置执行，再根据 Outcome 进入下一节点。不同 Contact 可在同一时刻处于不同节点。Wait 会延后推进；Split 会按条件选择路径；消息节点会触发对应发送流程。

## 4. 输入数据与输出数据
配置前确认 Activity 使用哪些数据：
- Entry / Journey Data：本次进入时携带的数据。
- Contact Data：Contact Builder 关联的客户属性。
- Activity Output：某些 Activity 产生并可供下游使用的输出。

不要默认某个 Activity 的输出字段自动对后续节点可见；需要检查该 Activity 的输出 schema / 配置和下游引用。

## 5. 设计建议
1. 先画流程图，再在 Canvas 配置。
2. 每个节点只承担明确职责。
3. 对每个 Split 设计所有分支，包括 Remainder。
4. 为关键节点定义输入字段、输出字段和失败处理。
5. 避免无意义的多层分支和过长等待链。
6. 通过 Test Mode 和测试 Contact 验证路径。

## 6. 故障排查
- Contact 未推进：确认前一 Activity 是否完成、Wait 是否到期、Journey 是否运行。
- 分支不正确：确认字段来源、数据关系、条件顺序和空值。
- 消息未发：确认消息配置、发送资格、订阅状态和发送日志。
- 自定义 Activity 异常：确认 Endpoint、认证、超时、请求/响应 schema。

## Checklist
- [ ] Activity 类别和许可符合需求
- [ ] 每个节点输入数据明确
- [ ] 输出数据能被下游正确引用
- [ ] 分支和 Remainder 路径完整
- [ ] 异常、等待和重试策略明确
