# 16. Journey 监控

## 学习目标
掌握 Journey 运行期间的入口、Activity、错误和发送监控，以及安全排障流程。

## 1. 监控维度
| 维度 | 监控内容 |
|---|---|
| Journey 状态 | Draft / Running / Stopped 等 |
| Entry | 进入人数、入口错误、重复进入 |
| Activity | 各节点通过人数、等待人数、异常 |
| Email | 发送、Bounce、Unsubscribe、Open、Click |
| Exit / Goal | 退出人数、目标达成数 |
| 数据 | DE 更新、Contact Data 关系、同步延迟 |

## 2. 监控路径
`Journey Status → Entry Source / Event → Contact History / Activity → Email Send / Tracking → Exit / Goal`
先定位 Contact 停留在哪个节点，再检查该节点的配置和依赖数据。

## 3. 故障排查步骤
1. 确认 Journey 和对应版本是否 Running。
2. 使用 Contact Key / 事件 ID 定位 Contact。
3. 查看 Journey History / Activity 结果。
4. 检查前置节点是否完成、Wait 是否到期。
5. 检查分支字段、数据来源和关系。
6. 若是发送问题，检查发送资格、Subscriber Status、Send Log 与 Tracking。
7. 记录受影响 Contact 范围，再决定补偿或重新触发。

## 4. 安全重跑原则
不要因为没有看到邮件就立即重新导入或重发。先确认原事件是否已进入、消息是否已触发、是否已发送以及是否有退信。重复触发可能造成重复营销邮件。必要时用业务 Event ID 和发送记录进行去重。

## 5. 常见异常
- 入口数为 0：入口事件、DE、筛选条件、Contact Key。
- Activity 数量断层：前一节点执行、Split 条件、Wait。
- Email 发送数少于节点人数：发送资格、订阅状态、抑制规则。
- Wait 人数长期不变：等待设置、时区、Journey 状态。
- Goal 数量异常：过滤条件、数据关系、评估周期。

## Checklist
- [ ] 关键 Journey 有负责人和监控频率
- [ ] 入口、Activity、发送、退出指标有基线
- [ ] 故障可按 Contact Key / Event ID 定位
- [ ] 重试前已确认是否产生副作用
- [ ] 故障记录包含时间、版本、范围和处置
