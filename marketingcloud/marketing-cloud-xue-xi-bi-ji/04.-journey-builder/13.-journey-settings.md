# 13. Journey Settings

## 学习目标
理解 Journey Settings 中影响 Contact 进入、重复进入、默认发送和时区的关键设置。

## 1. 主要设置
不同入口和 Journey 类型的设置项有所差异，通常需要重点检查 Contact Entry / Re-entry、Contact Key 及入口映射、默认 Email 地址或发送相关选项（如适用）、时区和发送时间相关配置。

## 2. Re-entry 策略
Re-entry 决定 Contact 是否以及何时能再次进入同一 Journey。常见策略概念包括：
- No re-entry：同一 Contact 不允许再次进入。
- Re-entry after exiting：Contact 退出后才允许再次进入。
- Re-entry anytime：允许在旅程仍有一次执行时再次进入（具体并发/重复约束以当前 UI 为准）。

选项名称和适用限制可能随 Journey 类型或产品更新变化，应以实际 UI 为准。

## 3. 设计判断
| 场景 | 设计考虑 |
|---|---|
| 一次性欢迎邮件 | 通常限制重复进入，避免重复欢迎 |
| 每次订单触发的订单通知 | 需要按订单事件重复进入，并用事件 ID 区分订单 |
| 每月活动提醒 | 明确每月是否允许重新进入，以及上次旅程是否必须结束 |
| 长期培育旅程 | 避免同一 Contact 同时处于多个冲突旅程 |

## 4. Contact Key
Contact Key 必须在入口、Contact Builder 和渠道发送之间保持一致。若同一个自然人使用不同 Key，平台可能将其识别为不同 Contact，造成重复触达和数据分散。

## 5. 操作与验证
1. 打开 Journey Settings。
2. 检查当前 Contact Entry / Re-entry 选项。
3. 检查入口字段和 Contact Key。
4. 明确时区和发送时点。
5. 用同一 Contact 连续触发两次、旅程中再次触发、退出后再次触发等场景验证。

## 常见问题
- Contact 无法二次进入：检查 Re-entry 规则及当前执行状态。
- Contact 重复进入：检查入口事件重复、Contact Key 不一致和允许重入策略。
- 进入频率不符合预期：检查入口触发机制与业务端事件控制。

## Checklist
- [ ] Re-entry 策略符合业务场景
- [ ] Contact Key 跨渠道一致
- [ ] 并发旅程和重复触发风险已评估
- [ ] 时区与发送时点明确
