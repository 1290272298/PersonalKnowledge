# 15. Journey 发布

## 学习目标
掌握 Journey 的 Validate、Test、Activate 发布步骤和发布前控制。

## 1. 发布流程
`Design → Configure → Validate → Test → Approval → Activate → Monitor`
Validate 主要检查配置错误和必需项；Test 用于验证业务逻辑。二者不能互相替代。

## 2. Validate
检查入口、Activity 配置、必需字段、消息引用、Split、Wait、Goal 和 Exit Criteria。若存在错误，先修复再进入正式发布。

## 3. Test
使用具有代表性的测试 Contact 覆盖正常入口、无效入口、重复事件、每个 Split 分支及 Remainder、空值和异常状态、Email 个性化、发送资格、Exit Criteria / Goal，以及不同时区和等待边界。

Test Mode 与真实生产发送的行为可能不同；测试结果不能替代生产发布后的监控。

## 4. Activate
正式激活前，确认发布窗口、入口数据准备、发送许可、业务审批和监控负责人。激活后立即确认 Journey 状态、入口数量和首批 Contact 路径。

## 5. 发布前 Checklist
- [ ] 入口与 Contact Key 正确
- [ ] Entry Event / DE 字段完整
- [ ] 所有 Activity 已配置
- [ ] Split 分支和 Remainder 已测试
- [ ] Wait / 时区已验证
- [ ] Email 内容和发送配置已确认
- [ ] Exit Criteria / Goal 已验证
- [ ] Re-entry 与版本切换策略已确认
- [ ] 业务审批和发布窗口已确认
- [ ] 监控和故障联系人已就绪

## 常见问题
- Validate 通过但流程不正确：补做端到端测试和边界数据测试。
- 激活后无人进入：检查入口数据、触发事件、Journey 状态和 Contact Key。
- 激活后发送异常：按 Activity History、发送日志和订阅状态逐层排查。
