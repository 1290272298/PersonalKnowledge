# 03. Entry Source

## 学习目标
理解入口数据源类型、入口数据结构、Contact Key 映射和入口数据快照的设计影响。

## 1. Entry Source 是什么
Entry Source 定义 Journey 从哪里取得进入事件/联系人。所有 Journey 都必须有入口。入口类型及可用选项依账号配置而异，常见包括 Data Extension、API Event、Salesforce Data、Audience 或其他受支持事件。

## 2. 常见入口类型
| 类型 | 常见触发方式 | 设计重点 |
|---|---|---|
| Data Extension | 依据 DE 入口配置评估符合条件的记录 | Sendable Relationship、字段结构、入口筛选 |
| API Event | 外部系统调用事件接口 | Event Definition Key、Contact Key、幂等和重试 |
| Salesforce Data | CRM 记录创建/更新等事件 | Connector、对象权限、字段映射、同步配置 |
| Audience / 其他入口 | 由支持的受众或事件来源触发 | 受众定义、刷新周期、许可与配置 |

## 3. Data Extension Entry
入口 DE 常见字段示例：
| 字段 | 用途 |
|---|---|
| ContactKey | 识别 Contact |
| EmailAddress | 邮件地址 |
| EventId | 业务事件唯一标识 |
| EventDate | 事件时间 |
| Status | 入口过滤或后续判断 |
| Locale | 内容个性化 |

检查 Sendable Relationship 是否将正确字段关联到 Subscribers / Contact Key。不要只因为 DE 中存在 ContactKey 字段，就认定 Journey 一定使用了该字段。

## 4. 入口数据与字段快照
Journey 入口字段结构、字段映射和事件定义会影响已发布版本。修改入口字段或事件配置前，确认是否需要创建新版本；不要假定已激活版本会自动读取新增字段。入口记录也不等于实时主档数据。

## 5. 设计步骤
1. 选择最符合业务事件的 Entry Source。
2. 定义稳定 Contact Key 和事件唯一标识。
3. 设计最小必要字段，避免将无关个人数据带入 Journey。
4. 定义记录筛选、事件触发、数据刷新和重复事件策略。
5. 检查字段类型、空值、时区和日期格式。
6. 用正向、负向和重复记录测试入口。

## 6. 常见问题
- 没有进入：检查入口状态、DE 记录/筛选条件、事件调用、Contact Key。
- 进入重复：检查事件重试、事件唯一 ID 和 Re-entry 设置。
- 分支读不到字段：检查 Journey Data / Contact Data 及入口字段是否可用。
- 修改字段后旧版本异常：检查版本入口快照和新版本配置。

## Checklist
- [ ] Entry Source 类型符合业务触发方式
- [ ] Contact Key 映射一致
- [ ] 字段类型和必填字段正确
- [ ] 入口过滤和刷新周期清晰
- [ ] 重复事件、迟到数据和重试已考虑
