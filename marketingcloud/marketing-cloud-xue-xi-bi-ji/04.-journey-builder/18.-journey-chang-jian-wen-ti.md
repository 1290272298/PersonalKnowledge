# 18. Journey 常见问题

## 1. Contact 没有进入 Journey
排查顺序：
1. Journey 版本是否已 Activate。
2. Entry Source / Event Definition 是否正确。
3. DE 记录、入口过滤或 API Event 是否实际产生。
4. Contact Key 是否为空、错误或与其他渠道不一致。
5. Re-entry 规则是否阻止再次进入。
6. 入口字段结构是否与已激活版本一致。

## 2. Contact 进入了错误分支
检查 Journey Data / Contact Data 选项、Contact Builder Attribute Group 关系、字段更新时间、空值和数据类型。Decision Split 按顺序评估，检查条件优先级与 Remainder；Engagement Split 则确认关联的消息 Activity、Wait 和 Tracking。

## 3. Email Activity 没有发送
确认 Contact 是否到达该节点；检查 Subscriber Status、Held、退订和抑制规则；检查 Email、Send Classification、Sender / Delivery Profile；检查发送日志和 Tracking，不要只凭收件箱未见邮件判断未发送。

## 4. Contact 长时间停留在 Wait
检查 Wait 类型、时长、时区、夏令时、Journey 状态，以及是否存在退出或目标评估。用 Contact 的实际进入时间计算预期释放时间。

## 5. Contact 重复进入
检查 Contact Key 是否统一、Entry Event 是否重复发送、API 重试是否幂等、Re-entry 策略是否允许，以及是否存在多个 Journey 接收相同业务事件。

## 6. Goal / Exit Criteria 不生效
检查过滤字段、数据关系、数据刷新时点、评估机制及 Goal Exit Option。Goal 达成统计与退出动作不是同一件事。

## 7. 发布新版本后路径不同
检查新旧版本入口定义、在途 Contact 处理策略、字段变更和新版本发布选项。不要默认所有旧 Contact 都会自动迁移。

## 8. 故障记录模板
| 项目 | 记录内容 |
|---|---|
| 发生时间 | 含时区 |
| Journey / Version | 名称和版本 |
| Contact Key / Event ID | 使用受控的测试标识或脱敏值 |
| Activity | 异常节点 |
| 预期 / 实际 | 可复现的差异 |
| 影响范围 | Contact 数量、消息数量 |
| 原因 | 数据、配置、权限或平台 |
| 处置 | 修复、补偿、重跑及防复发 |

## Checklist
- [ ] 按节点逐层排查而不是直接重跑
- [ ] 记录 Journey Version 与 Contact Key
- [ ] 先确认是否已发送再补偿
- [ ] 对数据关系和评估时点进行验证
