# 12. Goal

## 学习目标
理解 Goal 的业务衡量意义、目标过滤器、统计和退出选项。

## 1. Goal 是什么
Goal 用于衡量 Journey 希望 Contact 达成的行为，例如购买、注册、预约或申请。Goal 基于 Contact 数据过滤条件定义；Journey 激活后按产品机制评估 Contact 是否满足目标。

## 2. Goal 与 Exit Option
Goal 是可选配置。设置目标后可统计目标达成情况；若启用对应 Exit Option，Contact 达成 Goal 后可按规则退出旅程。未启用退出选项时，Goal 仍可用于衡量，但不会因为达成目标而自动提前离开旅程。

Salesforce 文档说明，Goal 评估存在周期性机制；选择退出选项时，Contact 可在 Wait 阶段被评估，并可能提前离开 Wait/旅程。实际评估时点需按当前产品行为和配置验证。

## 3. 目标定义
示例：购买转化 Journey
- Goal：订单状态 = Completed
- 数据源：订单 DE 与 Contact 的关系
- 目标口径：按 Contact 是否满足条件计数
- 退出选项：若业务要求购买后不再发送后续促销，可启用并测试

## 4. Goal Rate
`Goal Rate = 达成 Goal 的 Contact 数 ÷ 参与统计的 Contact 数 × 100%`
应明确分母口径、统计窗口、重复订单和重复 Contact 的处理方式，避免把 Journey Entry 数直接当成业务转化人数。

## 5. Goal 与 KPI
Goal 是 Journey 中可配置的目标衡量机制；KPI 是更广义的业务指标。一个业务 KPI 可能需要外部 BI、订单系统或数据仓库共同计算，不能认为 Goal 自动等于完整业务 ROI。

## 常见问题
- Goal 计数为 0：检查条件字段、数据关系、数据刷新和评估时点。
- 达成 Goal 后仍收到邮件：检查是否启用 Exit Option、Wait 评估时点，以及发送是否已触发。
- 统计比例异常：确认分母、Contact 去重、重复进入和统计周期。

## Checklist
- [ ] Goal 反映明确业务行为
- [ ] 过滤条件和数据源正确
- [ ] Goal 统计口径清晰
- [ ] 是否退出由 Exit Option 明确控制
- [ ] 评估时点和已触发消息风险已验证
