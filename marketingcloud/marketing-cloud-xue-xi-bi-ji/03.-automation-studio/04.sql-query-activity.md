# 04. SQL Query Activity

## 1. 学习目标
能够使用 SQL Query Activity 从 Data Extension 和 Data Views 读取数据，将结果写入目标 DE，并理解 Overwrite、Append、Update、主键和性能限制。

## 2. SQL Query Activity 是什么
SQL Query Activity 在 Automation Studio 中执行 SQL 查询，常用于筛选、JOIN、聚合和转换 Marketing Cloud Engagement 数据，并将结果写入指定 Target Data Extension。

适合处理结构清晰、已在 Marketing Cloud 中准备好的数据。超大规模数据整合或复杂分析通常应评估企业数据仓库等外部方案。

## 3. 基本查询
    SELECT
        SubscriberKey,
        EmailAddress
    FROM CustomerDE
    WHERE Status = 'Active'

DE 名称和字段名必须与实际对象一致。SQL Query Activity 使用受支持的 SQL 子集，不应直接假设所有 SQL Server 语法都可用。

## 4. JOIN 示例
    SELECT
        c.SubscriberKey,
        c.EmailAddress,
        o.OrderDate
    FROM CustomerDE AS c
    INNER JOIN OrderDE AS o
        ON c.SubscriberKey = o.SubscriberKey

执行前确认 JOIN Key 的业务含义、是否会造成结果行数膨胀、目标 DE 是否允许重复 Key，以及 NULL 和数据类型是否兼容。

## 5. Target DE 与 Data Action
| Data Action | 作用 | 常见用途 |
|---|---|---|
| Overwrite | 清空目标 DE 后写入本次结果 | 每次重新生成完整快照 |
| Append | 将本次结果追加到目标 DE | 日志或历史记录 |
| Update | 按目标 DE 的主键更新匹配记录 | 更新已存在的数据 |
| Update / Append（如界面提供） | 更新匹配记录，并插入新记录 | 维护增量目标表 |

具体选项和行为以当前 SQL Query Activity 界面为准。Overwrite 风险较高，运行前必须确认目标 DE 和数据范围。

## 6. 主键与重复数据
- Target DE 的 Primary Key 决定唯一性约束。
- Append 遇到重复主键可能导致写入失败。
- Update 依赖目标 DE 中的匹配键；不能把它理解成任意字段自动匹配。
- JOIN 造成重复行时，可能触发 Duplicate Key 错误。
- 需要一行一用户时，应在 SQL 中明确去重规则，不能仅依赖目标 DE 约束。

## 7. 性能与执行限制
- Salesforce 文档说明 SQL Query Activity 有 30 分钟超时限制。
- 如果查询持续运行超过约 10 分钟，应考虑优化或将大型数据处理迁移到更合适的数据平台。
- 可通过拆分中间表、减少不必要字段、提前过滤、优化 JOIN 条件等方式降低处理量。
- Query 与 Filter Activity 的并发执行存在平台限制；超过限制的任务会排队。官方参考说明可同时运行的 Query / Filter 数量上限为 40，具体以账号和文档更新为准。
- SQL Query Activity 在连续多次系统错误后可能被暂停；应查看 Action Log 并处理根因，不要只反复点击重跑。

## 8. 实际操作：创建 SQL Query Activity
1. 打开 Automation Studio → Activities。
2. 创建 SQL Query Activity。
3. 填写 Name、External Key（如适用）和说明。
4. 编写 SQL，确认 Source DE / Data Views。
5. 选择 Target DE。
6. 选择 Data Action。
7. 检查目标字段、字段类型、主键和记录数预期。
8. 保存后先手动执行。
9. 检查执行状态、错误信息、目标 DE 记录数和样例数据。
10. 验证通过后加入 Automation，并放在依赖数据已准备完成的后续 Step。

## 9. 常见问题
**Q1：Duplicate Key 错误**
检查 SELECT 结果是否存在重复主键、JOIN 是否扩大行数，以及目标 DE 的 Primary Key。

**Q2：字段长度或类型错误**
比较 SELECT 输出类型与 Target DE 字段类型、长度和可空设置；必要时 CAST / CONVERT 或调整数据设计。

**Q3：Query Timeout**
检查查询范围、JOIN、函数、Data Views 使用方式和数据量；拆分查询并使用中间 DE。

**Q4：Activity 被 Suspended**
查看 Automation / Query 的 Action Log，确认系统错误或连续失败原因，修复后按官方流程恢复。
