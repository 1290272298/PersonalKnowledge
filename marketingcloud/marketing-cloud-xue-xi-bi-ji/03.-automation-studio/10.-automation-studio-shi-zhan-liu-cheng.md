# 10. Automation Studio 实战流程

## 1. 学习目标
通过端到端案例理解 Automation Studio 的设计方法，能够将文件导入、数据加工、导出交付和监控组织为可维护的流程。

## 2. 场景说明
假设上游系统每天生成一份会员 CSV 文件，Marketing Cloud 需要导入文件、筛选有效会员、生成外部系统所需文件，并交付到指定 SFTP。

以下名称均为虚构示例，实际项目应替换为经过确认的文件规范、DE 和 FTP Location。

## 3. 流程总览
    Schedule / File Drop
          ↓
    Step 1：File Transfer（仅在需要解压/解密时）
          ↓
    Step 2：Import Activity
          ↓
    Step 3：SQL Query Activity
          ↓
    Step 4：Data Extract Activity
          ↓
    Step 5：File Transfer
          ↓
    External SFTP

如果源文件已是可直接导入的未压缩文件，可省略前置 File Transfer。若导出文件需要加密或压缩，也应按下游要求增加相应处理。

## 4. 数据对象设计
### Source DE
| 字段 | 示例类型 | 用途 |
|---|---|---|
| SubscriberKey | Text | 会员唯一标识 |
| EmailAddress | EmailAddress | 邮件地址 |
| Status | Text | 会员状态 |
| UpdateDate | Date | 数据更新时间 |

### Target DE
| 字段 | 示例类型 | 用途 |
|---|---|---|
| SubscriberKey | Text | 会员唯一标识 |
| EmailAddress | EmailAddress | 邮件地址 |
| UpdateDate | Date | 数据更新时间 |

主键、字段长度、可空性和业务去重规则应根据真实接口契约设计。

## 5. Step 设计
| Step | Activity | 输入 | 输出 / 结果 |
|---|---|---|---|
| 1 | File Transfer（可选） | 压缩 / 加密文件 | Safehouse 中可用文件 |
| 2 | Import | CSV / TXT | Source DE |
| 3 | SQL Query | Source DE | Target DE |
| 4 | Data Extract | Target DE | 导出文件 |
| 5 | File Transfer | 导出文件 | 外部 SFTP |

依赖前一阶段结果的 Activity 应放在后续 Step，不要假设同一 Step 内 Activity 按画面排列顺序串行执行。

## 6. SQL 示例
    SELECT
        SubscriberKey,
        EmailAddress,
        UpdateDate
    FROM SourceMemberDE
    WHERE Status = 'Active'

目标 DE 使用 Overwrite 还是 Update / Append，取决于业务需要的是完整快照还是增量数据。选择前必须明确历史数据是否需要保留。

## 7. 上线前测试
1. 准备少量测试文件，覆盖正常数据、空值、重复 Key 和错误格式。
2. 验证 File Transfer（如适用）能正确处理文件。
3. 验证 Import 的编码、字段映射和 Data Action。
4. 验证 SQL 结果行数和目标字段。
5. 验证 Data Extract 文件格式、编码和文件名。
6. 验证 File Transfer 已将文件送达正确 SFTP。
7. 模拟文件缺失、导入失败和下游不可用等异常。
8. 验证重跑不会重复导入或重复覆盖错误数据。
9. 由业务负责人确认最终数据。

## 8. 运行监控与验收标准
| 验收项目 | 示例标准 |
|---|---|
| 启动时间 | 在约定窗口内启动 |
| Import | 文件存在，导入结果符合预期 |
| SQL | 目标 DE 记录数与预期一致 |
| Extract | 文件生成且字段、编码正确 |
| Transfer | 外部 SFTP 收到目标文件 |
| 重复处理 | 同一批文件重复触发时有明确处理规则 |
| 异常处理 | 失败能定位，重跑前能判断副作用 |

## 9. 项目设计文档建议
每个 Automation 至少记录目的、业务负责人和运行频率、BU、Automation Name / External Key、启动方式和时区、Step / Activity 顺序和参数、源文件名和字段规范、Source / Target DE、主键和 Data Action、成功条件、失败通知和重跑方式，以及是否包含发送操作。

## 10. 学习 Checklist
- [ ] 能设计文件到 DE 的导入流程。
- [ ] 能设计 DE 到外部系统的导出流程。
- [ ] 能根据数据依赖拆分 Step。
- [ ] 能定义记录数、文件和下游验收条件。
- [ ] 能设计失败后的安全重跑方案。
