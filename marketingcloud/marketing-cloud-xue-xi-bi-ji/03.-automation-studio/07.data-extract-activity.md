# 07. Data Extract Activity

## 1. 学习目标
理解 Data Extract Activity 的用途，能够区分数据提取与文件传输，并设计从 Marketing Cloud 生成文件、再交付外部系统的流程。

## 2. Data Extract Activity 是什么
Data Extract Activity 用于生成可在 Marketing Cloud Engagement 外部使用的文件。它可提取受支持的数据，也可将 XML 文件转换为 CSV、Tab 或 Pipe 等分隔格式。

注意：Data Extract 负责生成文件，不等同于把文件上传到外部 SFTP。通常需要后续 File Transfer Activity 完成文件交付。

## 3. 常见应用场景
- 导出 Data Extension 数据。
- 导出 Tracking / 报表相关数据（需使用对应支持的 Extract Type）。
- 将平台数据提供给外部 DWH、CRM 或其他系统。
- 将 XML 转换为外部系统要求的分隔文件格式。

不同 Extract Type 支持的数据源和输出结构不同，不能认为任意 Data Extension 都能通过同一种 Extract Type 导出。

## 4. 典型导出流程
    Marketing Cloud 数据
           ↓
    Data Extract Activity
           ↓
    生成 Extract 文件
           ↓
    File Transfer Activity
           ↓
    目标 FTP / SFTP
           ↓
    外部系统

## 5. 设计时需要确认
- Extract Type 是否支持目标数据。
- 输出文件格式、分隔符和编码。
- 文件名规则、日期变量和重复执行时的命名策略。
- 是否需要压缩或加密。
- 输出目录、目标 FTP Location 和访问权限。
- 下游系统的文件到达窗口和处理完成确认。

## 6. 实际操作：创建导出流程
1. 确认要导出的数据类型和下游文件规范。
2. 在 Automation Studio → Activities 创建 Data Extract Activity。
3. 选择适合的 Extract Type 并配置参数。
4. 设置文件名和输出格式。
5. 保存后在测试数据范围内运行。
6. 检查生成文件的字段、编码、分隔符和记录数。
7. 将 File Transfer Activity 放在后续 Step。
8. 检查外部 FTP 是否收到文件，并验证下游可正常读取。

## 7. 常见问题
**Q1：Data Extract 完成但外部 FTP 没有文件**
检查是否配置后续 File Transfer、目标 FTP Location、文件名和执行 Step。

**Q2：导出字段或格式不符合预期**
确认 Extract Type、输出格式、日期格式、编码和下游文件规范。

**Q3：文件名被覆盖**
使用包含业务日期或运行批次的命名策略，并确认平台支持的文件名替换变量。
