# 03. Schedule 与启动方式

## 1. 学习目标
理解 Automation 的常见启动方式，能够根据业务场景选择一次执行、定时执行、文件触发或 API 启动，并正确考虑时区和重复执行风险。

## 2. Schedule 是什么
Schedule 用于按预先定义的时间规则启动 Automation。它决定 Automation 何时开始，而不是为每个 Activity 分别设置执行时间。

## 3. 常见启动方式
| 启动方式 | 说明 | 适用场景 |
|---|---|---|
| Run Once / Immediate | 手动立即执行一次 | 测试、补跑、临时任务 |
| Schedule | 按固定时间或周期启动 | 日次、周次、月次批处理 |
| File Drop | 指定目录出现符合规则的文件后启动 | 上游系统文件到达后处理 |
| API / Trigger | 由外部系统或 API 触发 | 系统间事件驱动流程 |

实际可选项取决于账号功能、权限和 Automation 类型。

## 4. 时间与时区
设置 Schedule 前必须确认 Automation 使用的时区和账号时区、业务要求的当地时间、夏令时、上游文件生成时间和下游接收窗口，以及任务是否可能超过下一个计划启动时间。

不要只根据电脑本地时间推断 Automation 的实际执行时间。应以账号配置和运行历史的时间戳验证。

## 5. File Drop 启动设计
File Drop 常用于上游系统生成文件后自动启动处理流程。设计时应明确：
- 监视的 FTP / SFTP Location。
- 文件名 Pattern。
- 文件是否压缩或加密。
- 是否可能出现同名文件、重复投递或部分上传。
- 文件到达后是否需要等待上传完成。
- 处理成功后如何归档或移动文件。

文件名 Pattern 应与上游约定一致，不能只依赖目录中有文件这一条件。

## 6. 实际操作：设置定时任务
1. 在测试 Automation 中选择 Schedule 启动方式。
2. 设定执行周期、日期和时间。
3. 确认时区以及首次运行时间。
4. 查看是否存在重复或冲突的 Automation。
5. 保存后进行一次手动测试。
6. 通过 Run History 核对实际启动时间。
7. 验证成功后再启用正式 Schedule。

## 7. 常见问题
**Q1：为什么 Automation 没有在预期的本地时间启动？**
检查账号时区、Schedule 设置、启动状态和 Run History，不要只查看个人电脑时间。

**Q2：每次文件到达都启动吗？**
取决于 File Drop 配置和文件 Pattern。应测试文件名匹配、重复文件及文件到达时机。

**Q3：上一次任务尚未完成，下一次 Schedule 到来怎么办？**
需要结合账号的并发执行和排队行为确认。设计上应避免任务重叠，并监控执行时长。

## 8. 学习 Checklist
- [ ] 能区分一次执行、Schedule、File Drop 和 API Trigger。
- [ ] 能确认任务使用的时区。
- [ ] 能设计文件名 Pattern 和文件到达规则。
- [ ] 能通过 Run History 核对实际启动时间。
- [ ] 能识别任务重叠和重复处理风险。
