# 08. Script Activity（SSJS）

## 1. 学习目标
理解 Script Activity 的用途和适用边界，能够判断何时使用 SQL、标准 Activity 或 SSJS，并了解脚本执行的权限、错误处理和安全要求。

## 2. Script Activity 是什么
Script Activity 用于在 Automation Studio 中执行 Server-Side JavaScript（SSJS）。它适合实现标准 Activity 不便表达的条件逻辑、API 调用和定制处理。

它不是默认的数据批处理工具。对于大批量筛选、JOIN 和聚合，通常优先考虑 SQL Query Activity。

## 3. SQL 与 SSJS 的选择
| 需求 | 建议方式 |
|---|---|
| 大量 DE 数据筛选、JOIN、聚合 | SQL Query Activity |
| 文件解压、移动、解密 | File Transfer Activity |
| 文件解析并导入 DE | Import Activity |
| 支持的数据导出 | Data Extract Activity |
| 条件分支、API 调用、特殊业务逻辑 | Script Activity（评估必要性） |

## 4. 示例：向 DE 写入一条测试记录
以下为结构示例，必须在测试 DE 中执行，并确认 External Key 与字段定义：

    <script runat="server">
    Platform.Load("Core", "1");

    var de = DataExtension.Init("YOUR_TEST_DE_EXTERNAL_KEY");
    var result = de.Rows.Add({
        SubscriberKey: "TEST001",
        Status: "Active"
    });

    Write(String(result));
    </script>

不要把示例中的 DE Key、字段名或测试值直接复制到生产环境。生产脚本还应处理异常、重复执行和日志记录。

## 5. 脚本设计要求
- 使用最小必要权限，避免使用不必要的管理员凭证。
- 不要在脚本中硬编码密码、Access Token 或 Secret。
- 对外部 API 设置超时、重试和错误处理策略。
- 对可能重复执行的脚本设计幂等逻辑。
- 对大数据量操作进行分页或分批，避免单次脚本超时。
- 记录必要的执行结果，但不要将个人信息或凭证写入日志。
- 对异常使用 try / catch，并将错误传递到可监控的结果中。

## 6. 实际操作：创建 Script Activity
1. 在 Automation Studio → Activities 创建 Script Activity。
2. 输入名称、External Key 和描述。
3. 编写 SSJS，并确认引用的 DE / API 对象。
4. 在测试 BU 和测试数据上执行。
5. 验证写入结果、返回结果和异常路径。
6. 将脚本加入 Automation，并明确它依赖的前置 Step。
7. 配置监控和失败后的处理方式。

## 7. 常见问题
**Q1：脚本执行成功但没有数据变化**
检查 DE External Key、字段名称、权限、输入数据和脚本执行分支。

**Q2：脚本偶发失败**
检查 API 响应、超时、限流、并发、临时服务异常和重试策略。

**Q3：是否应该用 SSJS 替代所有 SQL？**
不应该。数据集查询和批量转换通常更适合 SQL；SSJS 应用于需要程序控制的场景。
