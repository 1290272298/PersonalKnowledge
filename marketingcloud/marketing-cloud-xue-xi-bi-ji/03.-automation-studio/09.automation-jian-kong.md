# 09. Automation 监控与故障排查

## 1. 学习目标
能够通过 Automation Run History 和 Activity 结果定位失败步骤，结合输入输出数据、文件状态和日志判断原因，并安全地恢复任务。

## 2. 为什么需要监控
Automation 用于日次数据处理、文件导入、数据同步、邮件发送和外部系统连携。即使 Automation 显示 Completed，也需要确认业务结果是否正确。

建议至少监控：是否按计划启动、是否在 SLA 时间内完成、每个 Activity 是否成功、输入输出记录数是否符合预期、文件是否生成和传输、下游系统是否成功接收。

## 3. 运行结果检查
不同界面和 Activity 的状态名称可能不同。常见结果概念包括运行中、完成、错误、停止或跳过。

| 检查项 | 检查内容 |
|---|---|
| Automation Name | 是否为目标任务 |
| Run Start / End | 实际开始和结束时间 |
| Duration | 是否超过正常执行时间 |
| Step / Activity | 失败发生在哪个阶段 |
| Error Message | 错误信息和上下文 |
| Input / Output | 源记录数、目标记录数 |
| File | 文件名、目录、大小、时间 |
| Downstream | 下游是否已消费数据 |

## 4. 常见故障与排查

### 4.1 Import Error
可能原因：文件不存在或 Pattern 不匹配；Header、Delimiter、Encoding 或 Date Format 不正确；目标字段类型或长度不匹配；Primary Key 重复或必填字段为空；文件尚未完整上传。

排查：先确认源文件，再检查 Import Definition、Mapping、Data Action 和 Import 结果。

### 4.2 SQL Query Error
可能原因：SQL 语法或字段名错误；JOIN 产生重复主键；输出字段类型与 Target DE 不匹配；Query 超时或数据量过大；Data Views 查询范围或字段不符合要求。

排查：查看 Query / Action Log，先在测试数据范围验证 SQL，再检查 Target DE 和执行耗时。

### 4.3 File Transfer Error
可能原因：FTP Location、目录或权限错误；文件名不匹配；文件加密方式或压缩格式不受支持；远端 FTP 时间与 UTC 判断不一致；文件损坏或尚未上传完成。

排查：确认文件源、目标位置、密钥/压缩设置和文件时间。

### 4.4 Automation 未启动
检查 Schedule / File Drop / API Trigger 是否启用、时区和计划时间是否正确、File Drop Pattern 是否匹配、是否存在上次任务未完成或任务被暂停的情况，以及启动权限和账号配置是否发生变化。

## 5. 失败后的恢复原则
1. 先确认失败点和根因，不要立即重复执行。
2. 确认前置 Activity 是否已经产生部分结果。
3. 判断重跑是否会造成重复导入、重复发送或覆盖数据。
4. 必要时先备份目标 DE 或保留失败文件。
5. 修复配置或数据后，在测试范围验证。
6. 按批准流程重跑失败任务。
7. 对照记录数、文件和下游结果确认恢复成功。
8. 记录原因、影响范围、处理过程和防止再发措施。

特别注意：含 Send Email Activity 的 Automation 不可随意整体重跑，必须先确认是否已经发出邮件，避免重复发送。

## 6. 监控与告警建议
- 为关键 Automation 定义预期启动时间和完成 SLA。
- 对失败、未启动、执行时间异常和记录数异常设置告警。
- 记录 Automation 名称、Run ID、BU、时间范围和失败 Activity。
- 重要任务由业务负责人确认结果，而不仅依赖平台状态。

## 7. 学习 Checklist
- [ ] 能从 Run History 找到失败的 Automation 和 Activity。
- [ ] 能区分 Import、SQL、File Transfer 常见错误。
- [ ] 能核对记录数和文件结果。
- [ ] 重跑前会检查重复导入和重复发送风险。
- [ ] 能记录故障原因、影响和再发防止措施。
