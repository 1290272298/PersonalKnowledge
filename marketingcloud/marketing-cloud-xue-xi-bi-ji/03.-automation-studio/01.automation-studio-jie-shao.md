# 01. Automation Studio 介绍

## 1. 学习目标
理解 Automation Studio 在 Marketing Cloud Engagement 中的职责，能够说明它如何将数据处理、文件操作和发送任务组织成可重复执行的流程。

## 2. Automation Studio 是什么
Automation Studio 用于编排并执行一系列营销和数据管理任务。它可以按计划、文件到达或 API 等方式启动自动化，并按配置执行多个 Activity。

典型用途：
- 从 SFTP / FTP 导入文件到 Data Extension。
- 使用 SQL Query Activity 筛选、关联和加工数据。
- 将 Data Extension 或 Tracking 数据导出为文件。
- 通过 File Transfer 处理 Safehouse 中的文件。
- 执行 SSJS 脚本。
- 执行邮件发送或其他受支持的 Activity。

## 3. 与其他功能的关系
| 功能 | 主要职责 | 与 Automation Studio 的关系 |
|---|---|---|
| Contact Builder / Data Extension | 存储和组织数据 | Import、SQL 的数据源或目标 |
| Email Studio | 邮件内容、发送和 Tracking | 可由 Send Email Activity 调用发送 |
| FTP / SFTP | 文件交换 | 提供导入文件或接收导出文件的位置 |
| Journey Builder | 基于事件和受众执行旅程 | Automation 可准备或更新 Journey Entry 数据 |
| Script Activity | 执行 SSJS | 处理标准 Activity 不适合的程序逻辑 |

## 4. 典型数据流程
    外部系统
       ↓ CSV
    FTP / SFTP
       ↓
    File Transfer（如需解压/解密或移动）
       ↓
    Import
       ↓
    Source Data Extension
       ↓
    SQL Query
       ↓
    Target Data Extension
       ├─→ Journey Builder Entry
       ├─→ Email Send
       └─→ Data Extract → File Transfer → 外部系统

并非每条流程都需要 File Transfer。未加密、未压缩且位于可直接访问位置的文件，可能可以直接导入。

## 5. 核心概念
- Automation：整体自动化定义，包含启动方式和任务步骤。
- Schedule / Trigger：决定何时或由什么事件启动。
- Step：流程中的执行阶段。
- Activity：实际执行的任务，例如 SQL Query、Import 或 File Transfer。
- Run History：记录自动化运行情况，供监控和排障。

## 6. 实际操作：认识 Automation Studio
1. 登录 Marketing Cloud Engagement，确认当前 MID / BU。
2. 从导航进入 Automation Studio。
3. 查看 Automations，观察已有自动化的名称、状态和启动方式。
4. 打开 Activities，了解已创建的可复用 Activity。
5. 查看某个 Automation 的步骤配置和最近运行记录。
6. 仅在测试 BU 中创建练习用 Automation，不要修改生产任务。

## 7. 常见误区
- Automation 不等于单个 SQL，它可以编排多个不同 Activity。
- Schedule 不等于 Activity。Schedule 决定启动时机，Activity 执行具体工作。
- File Transfer 不等于 Import。前者处理文件，后者解析文件并写入数据目标。
- Data Extract 不一定自动把文件传到外部服务器，通常还需后续 File Transfer。
- Automation 显示 Completed 不代表业务数据一定正确，还要核对记录数、文件和目标数据。

- [ ] 能区分 Automation、Schedule、Step 和 Activity。
