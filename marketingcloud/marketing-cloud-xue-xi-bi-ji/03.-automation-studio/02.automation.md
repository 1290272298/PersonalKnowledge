# 02. Automation

## 1. 学习目标
理解 Automation 的组成、执行顺序和复用方式，能够根据数据依赖设计合理的 Step 与 Activity。

## 2. Automation 的结构
Automation 是一个由启动条件和一个或多个 Step 组成的流程。Step 中配置一个或多个 Activity。

    Automation
    ├─ Starting Source（Schedule / File Drop / API 等）
    ├─ Step 1
    │   └─ Activity
    ├─ Step 2
    │   ├─ Activity
    │   └─ Activity
    └─ Step 3
        └─ Activity

## 3. Step 与 Activity 的执行关系
- Automation 按 Step 顺序推进。
- 同一 Step 中的多个 Activity 通常作为同一阶段执行，不应把它们当作可保证先后顺序的串行任务。
- 后续 Step 应用于依赖前一阶段完成结果的任务。
- 如果 Activity B 必须读取 Activity A 刚刚生成的数据，应将它们放在不同 Step，避免并行执行造成读取时机不确定。

例如：

    Step 1：Import CSV
        ↓ 完成后
    Step 2：SQL Query
        ↓ 完成后
    Step 3：Data Extract
        ↓ 完成后
    Step 4：File Transfer

## 4. Activity 的可复用性
Activity 可以在 Activities 页面预先创建和配置，再加入一个或多个 Automation。修改一个被多个 Automation 共用的 Activity 时，应检查所有引用方，避免产生非预期影响。

## 5. 实际操作：创建 Automation
1. 进入 Automation Studio → Automations。
2. 选择创建 Automation。
3. 选择适合的 Starting Source，例如 Schedule 或 File Drop（可用选项依账号而定）。
4. 输入 Automation 名称和说明，使用可识别的命名规则。
5. 添加 Step，并将 Activity 放入对应 Step。
6. 按数据依赖安排 Step 顺序。
7. 配置每个 Activity 的参数和目标对象。
8. 保存后先在测试环境手动运行。
9. 检查每个 Step 的结果、数据数量和文件状态。
10. 验证无误后，再按变更流程启用 Schedule 或 Trigger。

## 6. 命名与设计建议
示例：AUTO_DAILY_MEMBER_IMPORT、AUTO_MONTHLY_CAMPAIGN_TARGET、AUTO_DAILY_TRACKING_EXPORT。

建议在设计文档中记录 Automation 名称 / External Key、启动方式和时区、Step 顺序、Activity 配置对象、Source / Target DE、文件名规则、失败后的重跑方式及通知负责人。

## 7. 常见问题
**Q1：为什么 SQL 读取不到同一个 Step 中 Import 刚导入的数据？**
同一 Step 中的 Activity 不应假定存在串行顺序。将 Import 和依赖它的 SQL 放在不同 Step。

**Q2：一个 Activity 能否被多个 Automation 使用？**
可以复用，但修改共享 Activity 前应评估所有引用的 Automation。

**Q3：Automation 显示 Completed 就代表业务成功吗？**
不一定。还需验证目标 DE 记录数、关键字段、文件是否生成及下游是否成功。

## 8. 学习 Checklist
- [ ] 能画出 Automation 的 Step / Activity 结构。
- [ ] 能解释 Step 顺序和同一 Step 内 Activity 的关系。
- [ ] 能根据数据依赖拆分 Step。
- [ ] 能记录 Automation 的启动方式、输入输出和失败处理。
- [ ] 修改共享 Activity 前会检查引用关系。
