# 04. 日本商务日语与说明文编写

*日语：ビジネス資料の日本語表現*

## 本章学习目标

- 写出明确的说明图标题。
- 用短句表达动作、条件和结果。
- 区分事实说明、请求确认、注意事项和待确认内容。
- 统一术语、缩写和系统名称。
- 避免中文直译、冗长敬语和模糊表达。

## 1. 说明图中的日语与邮件日语不同

说明图帮助读者快速识别对象、动作、条件和结果。图中文字通常比邮件正文短，但必须保留业务含义。

| 使用位置 | 表达特点 | 示例 |
|---|---|---|
| 图标题 | 对象明确 | ユーザーデータ連携処理の概要 |
| 流程框 | 一个主要动作 | データを取得 |
| 判断节点 | 可回答是/否 | 必須項目が設定されているか |
| 注释 | 补充条件 | ※対象データのみ |
| 注意事项 | 明确限制 | データ更新前に対象件数を確認する |
| 待确认 | 标识未定 | 要確認：通知方法 |

## 2. 标题写法

可使用“对象 + 内容 + 必要时的范围”：

| 模糊标题 | 更明确的标题 |
|---|---|
| 処理概要 | 注文データ取込処理の概要 |
| システム図 | 顧客管理システムの構成図 |
| データ連携 | 会員データの連携フロー |
| 操作方法 | ユーザー情報の更新手順 |
| エラー | データ取込時のエラー処理 |

标题不要写成长段说明，也不要只依赖文件名传达范围。

## 3. 常见动作表达

| 中文 | 日语表达 |
|---|---|
| 获取数据 | データを取得する／データ取得 |
| 注册数据 | データを登録する／データ登録 |
| 更新数据 | データを更新する／データ更新 |
| 删除数据 | データを削除する／データ削除 |
| 检查内容 | 内容を確認する／内容確認 |
| 判断条件 | 条件を判定する／条件判定 |
| 输出文件 | ファイルを出力する／ファイル出力 |
| 发送通知 | 通知を送信する／通知送信 |
| 传递数据 | データを連携する／データ連携 |

流程框可使用名词短语；正文说明按语法使用动词。不要为了形式统一而牺牲自然表达。

## 4. 条件和判断的表达

| 中文 | 推荐日语 |
|---|---|
| 是否存在数据？ | データが存在するか |
| 必填项是否完整？ | 必須項目がすべて設定されているか |
| 如果检查通过 | チェックに合格した場合 |
| 如果未通过 | チェックに不合格の場合 |
| 符合条件 | 条件を満たす |
| 不符合条件 | 条件を満たさない |

可以使用「OK／NG」，但首次出现时应定义判断标准。只写「正常」「异常」而不说明依据，读者可能无法验证。

## 5. 结果和状态表达

| 中文 | 日语 |
|---|---|
| 处理完成 | 処理完了 |
| 注册完成 | 登録完了 |
| 更新完成 | 更新完了 |
| 处理失败 | 処理失敗 |
| 审批通过 | 承認 |
| 审批未通过 | 否認 |
| 等待处理 | 処理待ち |
| 处理中 | 処理中 |

系统状态如果是固定枚举值，应严格使用系统实际定义，不要自行替换近义词。

## 6. 注意事项、前提和范围

| 目的 | 推荐表达 | 中文含义 |
|---|---|---|
| 前提 | 前提条件：～ | 前提条件 |
| 限制 | ～の場合に限る | 仅限于…… |
| 注意 | ～に注意する | 注意…… |
| 禁止 | ～しないこと | 不要执行…… |
| 待确认 | 要確認：～ | 需要确认…… |
| 范围外 | 本図の対象外 | 不属于本图范围 |
| 参考 | 参考：～ | 参考信息 |

「～してください」是面向读者的请求或指示。如果只是描述系统动作，不要误写成对用户的命令。

## 7. 避免中文直译

| 常见问题 | 推荐做法 | 原因 |
|---|---|---|
| 逐字翻译长句 | 拆成动作和条件 | 更适合图中文字 |
| 同一概念多个译名 | 统一项目术语 | 防止误认为不同对象 |
| 省略主语导致责任不明 | 必要时写出系统/担当者 | 明确执行主体 |
| 只写「正常」「异常」 | 写明判断条件 | 便于验证 |
| 过度使用敬语 | 按图表用途简洁表达 | 避免冗长 |
| 「确认」「检查」「验证」混用 | 按项目定义区分 | 避免概念混淆 |

例如：

不推荐：
~~~text
データを取得した後に、取得したデータの内容に対して確認を行う。
~~~

更简洁：
~~~text
データ取得後、必須項目を確認する。
~~~

如果是系统自动校验，可根据项目术语使用「チェック」「検証」等，不要只凭中文词面决定。

## 8. 编写图中文字的步骤

1. 先写原始业务事实，确保含义正确。
2. 把每个步骤拆成一个动作。
3. 明确判断条件和分支结果。
4. 查找项目已使用的日语术语。
5. 编写简洁日语。
6. 检查主语、条件和责任主体。
7. 请熟悉业务的人确认术语和业务含义。

建议建立术语表：

| 中文概念 | 项目日语 | 定义 | 确认状态 |
|---|---|---|---|
| 目标系统 | 連携先システム | 接收数据的系统 | 已确认 |
| 用户数据 | ユーザーデータ | 项目定义的数据对象 | 待确认 |
| 处理结果 | 処理結果 | 处理后产生的结果 | 已确认 |

## 9. 实际案例：把业务描述转换成图中文字

原文：

~~~text
系统获取订单数据，然后确认订单状态。如果订单状态是确定状态，就把数据登记到分析系统。如果不是确定状态，则不登记。
~~~

图中文字：

~~~text
注文データ取得
      ↓
注文ステータス確認
      ↓
ステータスが「確定」か？
   ┌──┴──┐
  はい    いいえ
   ↓       ↓
分析システムへ  登録対象外
データ登録
~~~

「確定」只是示例状态值。实际项目必须使用系统真实定义的状态名称。

## 10. 实际练习

A. 将「データについて」「処理の説明」「エラーについて」改成能体现对象和内容的标题。

B. 把长句「ユーザーが入力した情報を取得して、必須項目がすべて入力されているかどうかを確認する。」拆成适合流程框的日语。

C. 同一资料中出现「顧客情報」「ユーザー情報」「会員データ」时，列出需要确认的问题，说明为什么不能直接认定三者相同。

## 11. 完成标准

- [ ] 标题明确说明对象和内容。
- [ ] 一个流程框只表达一个主要动作。
- [ ] 判断条件可以明确判断。
- [ ] 正常和异常结果表达清楚。
- [ ] 术语与项目资料一致。
- [ ] 未确认的状态名和通知方式没有被擅自确定。
- [ ] 文字简洁但保留必要条件。
- [ ] 能解释为什么选择某种表达。

**达标成果：** 为一张简单的数据连携流程图编写标题、步骤、判断条件、结果和注意事项的日语文案。

## 12. 本章总结

说明图日语的关键是准确、简洁和统一。先保证业务含义，再缩短句子；先确认术语，再进行翻译。AI 可以辅助润色，但不能替代业务确认。
